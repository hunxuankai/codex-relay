# 顶部显示自检错误并支持跳转

## 目标

当系统自检存在错误项时，在主界面上方持续显示醒目的错误提示，让用户无需进入自检页也能发现问题，并可直接跳转到“系统自检”页面查看具体错误项。

## 已确认事实

- 主界面由 `src/App.vue` 管理 Providers、自检、备份和设置四个视图，当前通过本地 `activeView` 切换，无 Vue Router。
- `useHealth` 已在应用根组件中提供最新 `HealthReport`，报告包含汇总级别以及每个检查项的 `normal`、`warning`、`error` 级别。
- “系统自检”页面已展示完整检查项，无需新增后端接口或改变自检数据契约。
- 主界面顶部已有页头和应用通知区域，底部状态栏仅以文本显示自检汇总，不足以突出错误。
- 用户确认提示位于包含应用标题和主导航的页头正下方、当前页面内容上方，并采用横跨可用宽度的提示条。

## 需求

- 仅当最新自检报告中存在 `error` 检查项时，在主界面页头下方显示高可见度错误提示。
- 提示不得仅依赖颜色表达错误状态，应包含明确错误文案和可操作按钮。
- 提示应展示错误项数量，帮助用户判断问题规模。
- 用户点击提示中的查看操作后，应用切换到“系统自检”视图，并将主导航中的自检项标记为当前页面。
- 自检重新运行或事件更新后，如果不再存在错误项，提示应自动消失；warning 不作为本次顶部错误提示的触发条件。
- 首次设置向导和启动加载界面保持现有行为，不额外叠加此提示。

## 可观察行为切片

- 公开边界：挂载应用根组件后，通过可访问语义查询顶部自检错误提示和主导航。
- 输入/操作：向应用提供包含 `error` 检查项的响应式 `HealthReport`，然后点击“查看自检详情”。
- 预期结果：页头正下方显示包含准确错误数量的 `role="alert"` 提示；点击后“系统自检”页面可见，且自检导航项成为当前页面。
- 状态更新：把同一响应式报告替换为不含 `error` 检查项的报告后，提示自动消失。
- Mock 边界：组件测试 mock `useHealth`、`useProviders`、`useSettings` 等 composable，不 mock Vue 响应式更新，不调用真实 Tauri IPC、文件系统或用户目录。

## 验收标准

- [x] 给定自检报告包含一个或多个 `error` 检查项，进入正常主界面后，页头下方显示 `role="alert"` 的醒目提示，并显示准确的错误项数量。
- [x] 给定自检报告只有 `normal` 或 `warning` 检查项，主界面不显示顶部错误提示。
- [x] 点击“查看自检详情”后显示“系统自检”页面，且“打开自检”导航按钮的 `aria-current` 为 `page`。
- [x] 当响应式自检报告从 `error` 更新为无错误报告时，顶部提示自动消失。
- [x] 提示使用原生按钮，键盘可聚焦，窄窗口和明暗主题下保持可读。
- [x] 前端专项测试、类型检查和与本改动相关的样式契约检查通过。

## 范围外事项

- 不修改 Rust 自检逻辑、检查项判定或 Tauri IPC 契约。
- 不为 warning 增加同等级的顶部提示。
- 不引入 Vue Router、Pinia、桌面系统通知或新的持久化设置。
