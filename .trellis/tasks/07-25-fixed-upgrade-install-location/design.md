# 技术设计：固定升级安装目录并延后旧版卸载

## 设计结论

普通 NSIS 升级采用“原地覆盖”模式：检测到当前 per-machine NSIS 登记后，强制恢复登记目录，显示一个说明/确认页而不是维护单选项，跳过目录选择页，随后直接覆盖安装文件。这样与应用内 updater 的 `/P /UPDATE` 行为一致，取消安装时不会提前删除旧程序，也不会产生并存安装。

用户主动更换目录不属于本次升级路径。安装器在说明页告知用户先从 Windows 卸载旧版，再以新安装流程选择目录。旧 WiX 迁移仍保留原有卸载兼容路径，因为它没有相同的 NSIS 登记契约。

## 组件与边界

| 边界 | 责任 | 变化 |
|---|---|---|
| `custom-installer.nsi` `.onInit` | 识别 per-machine NSIS 登记并恢复路径 | 新增原地升级标志；即使存在 `/D=` 也不让已安装版本改目录 |
| `PageReinstall` | 告知用户升级方式并取得继续确认 | 普通 NSIS 不再渲染“不要卸载”单选项；保留 WiX 兼容 UI |
| 目录页 | 仅服务于新鲜安装/WiX 迁移 | 普通 NSIS 原地升级跳过 |
| `Section Install` | 写入新版文件和登记 | 依赖原地升级标志，不调用旧 NSIS 卸载器；保留现有快捷方式/自启 |
| README/spec/About | 对外说明行为契约 | 区分新装、应用内升级和手动重装 |
| `src/release-config.test.ts` | 结构回归门禁 | 锁定标志、页面顺序、无并存分支和新装回归 |

## 状态与数据流

```text
启动安装器
  -> SetContext / 读取已登记 NSIS 路径
  -> FreshInstall 或 InPlaceUpgrade
  -> PageReinstall（说明并确认；WiX 仍走兼容分支）
  -> Fresh/WiX 才显示目录页
  -> 用户确认安装
  -> SetOutPath + 覆盖文件 + 写入新登记
  -> 保留独立 Codex/Relay 数据与系统状态
```

`RestorePreviousInstallLocation` 是安装目录的唯一恢复点，并且只有产品目录键与 `UninstallString` 同时存在时才设置原地升级标志。普通卸载后残留的“上次目录”键不能锁住新鲜安装。原地升级不调用旧 NSIS 卸载器，因此不会触发普通卸载的快捷方式/开机自启清理；现有 `MainBinaryName` 清理逻辑继续处理旧主程序名。

## 兼容性与错误处理

- 新鲜安装：继续使用 D 盘固定磁盘检测、Program Files 回退、目录页和 `/D=`。
- 已登记 NSIS 安装：登记路径优先；目录页跳过；`/D=` 不得绕过原地升级保护。
- 应用内 updater：已有 `PassiveMode`/`UpdateMode` 分支保持兼容，不新增下载或签名逻辑。
- WiX 迁移：继续使用原有识别和卸载流程，作为显式兼容例外记录。
- 已登记路径为空或无法读取：按现有安装器错误路径失败，不猜测另一个目录。
- 安装文件写入失败：不得报告升级成功；保留真实失败证据。完整原子回滚不在本任务范围内，真实发布前必须通过隔离环境验证失败边界。

## 数据保留

安装目录只包含程序文件和安装元数据。`%USERPROFILE%\\.codex`、`%LOCALAPPDATA%\\CodexRelay`、API Key、日志和备份不由 NSIS 升级流程搬移或删除；文档继续遵循安全/数据保留规范。

## 重要权衡

- 选择原地覆盖而不是复制到新目录，避免旧卸载器删除新注册表、旧快捷方式和双份进程的风险。
- 不在本任务实现跨盘迁移，避免在 NSIS 中引入复制、失败回滚和权限竞态；未来若有需求，应建立独立迁移设计和真实 VM 验证。
- 通过结构测试锁定模板行为；真实安装/升级仍必须在隔离 Windows Sandbox/VM 中单独取得证据。
