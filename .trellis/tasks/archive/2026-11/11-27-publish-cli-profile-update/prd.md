# 发布 CLI Profile 更新

## 目标

将 `main` 上已完成的 CLI Profile 与供应商改进作为 Codex Relay `v0.5.4` 发布到 Windows 正式更新渠道，让已安装 `v0.5.3` 的用户可在设置页发现更新，也可手动下载安装器。

## 已确认事实

- 用户要求“线上发布更新”，范围是现有主分支到正式渠道的完整交付。
- 启动时 `main` 与 `origin/main` 同指向 `08dd3ad5d85c2cc8de8396a48383743e3638fbf8`，工作区干净；公开 Latest 为 `v0.5.3`，Release ID `420770763`，tag 为 `d381c9a1eb0057ce1495da9cf54fcb38cc9c43fb`。
- 发布范围包含 `ec84725`（CLI Profile 的 Windows 用户环境变量 Key）、`53ae3bf`（复用同供应商 Key）、`75908b3`（移除仅应用连接）与 `cd341ab`（切换后同步供应商详情）。

## 需求与约束

- 同步版本与最终简体中文说明；准确说明 Key 的作用范围、终端刷新、更新方式和 Windows 签名状态。
- 通过本地专项和完整检查、无 updater 私钥普通构建；GitHub Actions 只能先生成候选 SHA 对应的单个 Draft，审计合格后才公开同一 Release ID。
- 不读取或触及真实 Codex/Relay 数据，不读取签名私钥，不手动创建或推送 tag，不更改历史 Release 保留规则。

## 验收标准

- [x] 版本、锁文件与说明一致，发布请求校验、完整检查和普通 Windows 构建通过并有产物证据。
- [x] 精确提交与普通推送候选，唯一 Windows 发布 Run 绑定 `0.5.4` 和候选 SHA，CI 成功后仅生成 Draft。
- [x] 核对 Draft 的身份、目标、说明、三项资产与实际 updater 签名，随后公开并验证同一 Release ID、公开 tag 与固定 Latest 下载端点。
- [x] 核对历史清理 Run 及旧 Release、资产、tag 的状态，记录实际限制。
- Git 交付门禁：提交验证证据、归档和会话日志后，单独核对 `origin/main`、远端和本地 `HEAD`，结果在阶段 3.5 的最终交付中报告。

## 范围外

不修改既有功能、工作流、更新信任根及安装策略；除可实际取得的隔离验证证据外，不把打包、签名或公开下载等价为真实安装、UAC、应用内升级、重启、卸载或用户数据保留。
