# 一键切换的技术设计

- `prepare_profile_key_edit` 在原有写入资格检查之后，从默认配置确认同 ID 供应商，并只读查询 Relay 命名 Key。返回有序的 `providerKeys` 摘要（条目 ID、名称），不读 `auth.json`，不创建或修复密钥库。没有可用条目时返回空列表，手填不受影响。
- `apply_profile_provider_key({ profileName, token, apiKeyId })` 使用服务器保存的单次编辑基线确定 Profile、变量和供应商 ID；只接受打开时列出的条目。每个条目的名称和值指纹仅在后端基线中保留，不把明文、指纹或供应商选择提交给前端。
- 手填与按 ID 应用都使用相同的 `TransactionService::write_profile_environment`。在共享锁内的每次目标核验中核对所选条目指纹，避免在界面打开至写后确认期间无意使用已变更的来源。源冲突仍按原事务的取消、补偿和读回规则处理。
- Vue 弹窗以按钮展示可用名称，点击后调用专用 IPC，仅传条目 ID；沿用原有保存、互斥、状态刷新和终端提示。保留遮挡输入，不把已保存 Key 放入表单、前端状态或剪贴板。
- 不修改存储格式或注册表事务适配器；用户环境仍由既有保护管理。本轮不生成安装包，也不操作真实用户环境变量。
