# 修复发布远程 Run 失败

## 目标

修复 GitHub 发布 Run `30833079285` 在“运行完整检查”阶段暴露的 Windows 路径别名断言缺陷，
使发布控制台便携 EXE 的打包结构测试既能接受同一文件的 8.3 短路径与规范化长路径表示，又继续
验证实际交付文件、大小和 SHA-256。

## 已确认事实

- Run `30833079285` 的 `release` Job 在 Step #7“运行完整检查”失败，Step #8“构建 Draft
  Release”因此跳过；没有生成 Draft Release。
- 唯一失败用例是 `src/release-console-structure.test.ts:127` 的便携 EXE 打包证据断言；其余
  59 个测试文件、337 个测试通过。
- 失败时 Node 期望路径包含 `C:\Users\RUNNER~1`，PowerShell 打包脚本返回同一目录的长路径
  `C:\Users\runneradmin`；文件内容、大小和 SHA-256 没有差异。
- 本机普通临时目录下原测试 6/6 通过；使用临时 8.3 目录别名后可以稳定复现短路径输入与长路径
  证据的差异。
- `scripts/package-release-console.ps1` 通过 `Get-Item` 返回实际产物的完整路径。该行为是有效的
  构建证据，不应为了迎合测试而退化为输入字符串回显。

## 需求

- 测试必须显式覆盖 Windows 8.3 短路径输入，避免依赖运行器 `%TEMP%` 恰好采用哪种文本形式。
- 路径断言必须验证证据路径与预期产物是同一个真实文件，不能把等价路径的原始字符串拼写当成
  文件身份。
- 路径校验放宽后仍须校验复制后的字节、文件大小和 SHA-256；错误路径或不存在的路径必须继续
  失败。
- 不修改发布工作流、远端 Run 监控、生产打包脚本、版本文件或 Release 资产。
- 测试和诊断只使用系统临时目录，不读取、写入或删除真实 `.codex` 与
  `%LOCALAPPDATA%\CodexRelay`，不记录任何认证信息。
