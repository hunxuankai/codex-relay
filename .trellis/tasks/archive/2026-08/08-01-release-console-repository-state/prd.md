# 改进发布控制台仓库状态与版本展示

## 目标

让独立发布控制台在重复使用时减少无意义的重复输入，并在仓库预检阶段提供足够的线上版本上下文；同时向用户准确说明简体中文发布说明的生成机制。

## 用户请求

- 调查在发布控制台填写“Codex Relay 仓库”后，下次打开仍需再次填写的原因。
- 说明“生成简体中文发布说明”的真实生成链路，以及是否调用 Codex。
- 在“检查仓库”结果中显示当前线上最新版本号。

## 已确认事实

- `tools/release-console/src/App.vue` 当前以 `shallowRef('')` 初始化仓库路径，启动时没有加载、退出前也没有保存仓库偏好，因此进程关闭后必然要求重新填写。
- 发布会话本身保存在所选 worktree 的 Git 元数据目录中，但恢复会话前仍必须先知道仓库路径；现有会话状态无法承担“记住上次仓库”的入口偏好。
- `ReleaseNotesService` 是纯 Rust 确定性生成器，不调用 Codex、OpenAI API 或其他外部 AI。它读取 `v<本地 package.json 版本>..HEAD` 的 Git 提交主题，按 Conventional Commit 类型映射中文分类，过滤内部提交，并拼接固定中文模板；找不到对应 tag 时回退最近 20 条提交。
- 当前说明生成不会把英文提交主题翻译成中文，只保证标题、分类标签和固定说明为简体中文；维护者仍可编辑正文，发布前会校验必需段落、版本、安全提示和疑似秘密。
- 原始发布控制台 PRD 已要求预检读取公开 Latest，且明确“首版不调用外部 AI”；现有实现遗漏了预检结果中的 Latest 字段。
- 现有 GitHub 预检已经读取完整 Release 列表以统计 Draft，可从同一只读响应提取最新非 Draft、非 prerelease 的 tag，无需新增认证边界或额外外部写操作。
- 2026-08-01 本轮只读查询确认线上 Latest 为 `v0.4.0`，本地 `package.json` 版本也是 `0.4.0`。

## 需求

- R1：明确仓库字段当前的状态来源、生命周期和未持久化根因，不以猜测代替代码证据。
- R2：为仓库输入提供符合现有安全边界的持久化行为，使重新打开控制台时可恢复上次有效值；无有效历史值时仍使用现有默认或空态。
- R3：仓库预检成功后展示当前 GitHub `Latest Release` 的版本号；远端没有正式 Release 时显示明确空态，查询失败时保留真实错误而不伪造版本。
- R4：发布说明生成机制保持可审计，界面或文档中的说明必须与实际代码一致，不得暗示调用了未实际调用的 Codex/AI 服务。
- R5：不得读取、写入或删除真实 `%USERPROFILE%\.codex` 与 `%LOCALAPPDATA%\CodexRelay`；测试使用安全临时路径或成对 Relay 覆盖。
- R6：不得在日志、前端普通状态、任务材料或测试输出中暴露真实认证信息。
- R7：移除主界面“首版只完成可视化一键发布与在线复核；不执行 Sandbox、真实安装、UAC 或应用内升级。”横幅，不改变实际发布能力与证据边界。

## 验收标准

- [x] AC1：关闭并重新打开控制台后，上次通过校验的仓库输入会自动恢复，无需重复填写。
- [x] AC2：无持久化数据、数据损坏或版本不兼容时，控制台安全回退且仍可手动填写仓库。
- [x] AC3：仓库预检成功结果显示线上最新正式版本号，并能区分“没有正式 Release”与“查询失败”。
- [x] AC4：自动化测试覆盖仓库偏好保存/恢复、损坏回退、Latest Release 正常/空态/失败，以及前端展示。
- [x] AC5：发布说明生成机制的回答和用户可见文案均由代码与测试证据支持。
- [x] AC6：相关 Vue、Rust、发布专项测试与必要类型检查通过；未执行的真实 GitHub 写操作明确标注。
- [x] AC7：主界面不再显示首版范围横幅，其他发布流程和范围说明不受影响。

## 已批准方案

- 使用版本化 WebView 本地偏好保存最近一次预检成功后由后端返回的规范化本地仓库路径；读取或写入失败时安全回退为空值，不阻断手动输入与发布操作。
- 在现有 GitHub Release 列表预检响应中提取首个非 Draft、非 prerelease 的 tag，作为 `latestReleaseTag` 返回并在仓库摘要中显示；没有正式 Release 时显示“尚无正式版本”。
- 继续保持确定性、非 AI 的发布说明生成，并在发布说明区域明确提示“根据 Git 提交与固定模板生成，不调用 Codex”。
- 删除主界面首版范围横幅及其专用样式，不改变底层发布、安装和验证契约。
- 用户已于 2026-08-01 明确批准上述方案并要求实施。
