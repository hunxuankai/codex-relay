# 排查发布门禁失败并保留失败进度

## 目标

- 修复本地发布门禁主命令已经成功、但进程承载层把安全收尾误判为失败的问题。
- 保留本地门禁真实失败的安全分类，不再统一显示为“没有可用退出码”。
- 发布失败后持续显示准确失败步骤；关闭并重新打开发布控制台后仍保留，直到开始新一轮发布。

## 背景与已确认事实

- `full-project-check` 固定执行 `npm run check`。使用安全临时 `USERPROFILE`、`APPDATA`、
  `LOCALAPPDATA` 和 npm cache 直接运行同一命令时，检查输出包含完整成功尾部；stdout 为
  64,867 字节、stderr 为 2,977 字节，排除了脚本非零退出和 1 MiB 输出上限。
- 同一次发布中更早的 npm/cargo 命令已能通过相同 `SafeProcessRunner` 启动，且完整检查耗时远低于
  2 小时产品超时；结合无 stdin 等事实，失败收敛到主命令退出后的进程树收尾路径。
- `SafeProcessRunner` 在主命令退出后仍有 Job Object 后代超过 5 秒时，会调用
  `job.terminate()`，但无论终止是否成功都返回 `ProcessTreeTermination`。
- `ProcessLocalVerificationBackend` 除取消外会把全部 `ProcessError` 折叠成通用失败，后续只保留
  `exit_code=None`，因此现有事件无法说明真实进程错误类别。
- `ReleaseTimeline.vue` 对 `failed` 和 `cancelled` 会无条件把所有步骤置为“未开始”，这是失败后
  进度自动重置的直接原因。

## 需求

### R1：安全且真实的主命令完成语义

- 主命令已返回退出状态、但 Job Object 中仍有后代进程超过收尾宽限时，必须终止并验证完整退出。
- 若后代进程已被安全终止并验证，返回主命令的真实退出状态，不得虚构进程树终止失败。
- 只有无法安全终止或验证进程树时，才返回进程树终止失败。
- 不放宽命令超时、输出上限、取消或 Job Object 隔离。

### R2：保留本地门禁失败分类

- 非零退出继续保留具体命令 ID 与退出码。
- 进程后端失败必须保留安全分类，至少区分启动/恢复、超时、输出过大、进程树终止和输出读取失败。
- 稳定事件错误码继续使用 `RELEASE_LOCAL_VERIFICATION_FAILED`；消息基于实际保留的分类生成。
- 不把 stdout、stderr、环境变量、代理 URL、认证信息、PID 或进程命令行传播到事件和持久化状态。

### R3：持久化失败检查点

- 发布会话失败时，原子保存失败前阶段、具体 `stepId` 和稳定错误码。
- 新增字段必须兼容现有 schema version 1 会话；旧会话缺少检查点时仍可读取，不伪造历史失败位置。
- 新一轮发布创建新会话时清空旧失败检查点。

### R4：发布进度失败态

- 失败步骤之前的步骤显示“已完成”，失败步骤显示“失败”，之后步骤显示“未开始”。
- 本地固定命令必须映射到对应可见步骤：发布专项、完整检查或普通构建。
- 关闭并重新打开控制台后，从持久化会话恢复同一失败现场。
- 当前运行中的实时事件可作为兼容回退，但不能成为跨重启失败位置的唯一来源。
- 取消状态保持现有语义，本任务不把取消改成失败。

### R5：发布安全边界

- 候选回滚失败仍优先使用 `RELEASE_ROLLBACK_INCOMPLETE`，不得声称候选已完整回滚。
- 本地门禁失败不得继续 commit、push 或远端发布。
- 测试只能使用安全临时路径和明确的非真实 fixture，不得读取、写入或删除真实 Codex/Relay 数据目录。

## 验收标准

- [x] AC1：主进程退出 0、后代超过宽限但可被安全终止时，`SafeProcessRunner` 返回 `Some(0)`；
  无法安全终止时仍返回 `ProcessTreeTermination`。
- [x] AC2：本地门禁的非零退出与各类进程后端失败通过 service → orchestrator → application 保留
  具体命令和安全分类，事件不再统一显示“没有可用退出码”。
- [x] AC3：失败会话保存失败前阶段、具体步骤和稳定错误码，schema version 1 的旧会话可继续读取。
- [x] AC4：失败时间线显示此前完成步骤、当前失败步骤和后续未开始步骤；重启加载后结果不变。
- [x] AC5：新发布会话不继承旧失败检查点，实时事件晚到或重复不会覆盖新会话进度。
- [x] AC6：候选回滚、取消、commit/push 门禁及敏感信息边界不回归。
- [x] AC7：专项测试、真实生产进程后端探针、完整项目检查和发布控制台打包通过，并记录真实结果。

## 范围外

- 不改变四条本地发布门禁命令的集合、顺序或 2 小时超时。
- 不持久化完整发布事件日志、原始子进程输出、PID 或进程命令行。
- 不为旧的、已经缺失失败检查点的终态会话猜测精确步骤。
- 不改变 GitHub Actions、Draft 审计、公开 Release、历史清理或 updater 行为。
- 不重构全局 Windows 进程体系或引入第二套 Job Object 实现。
