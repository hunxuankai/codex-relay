# 展示 Provider 验证请求与响应

## 目标与用户价值

用户在“验证当前 Provider 配置”区域运行 API 可用性测试时，可以查看 Relay 实际发出的请求和 Provider 返回的结果，用于核对目标地址、模型、请求形状与响应内容，而不必只依赖“通过/失败”摘要。

## 已确认事实与约束

- Provider 可用性区域同时提供 API 可用性测试和 Codex 兼容性测试；结果只保存在当前前端会话，Provider 文件指纹变化后失效。
- API 可用性测试固定向当前 Base URL 的 `/responses` 端点发送一次无工具、非流式、最多 16 个输出 token 的请求；本任务继续使用 `stream=false`。
- Codex 兼容性测试通过受监控 gateway 验证流式 SSE；本任务不新增独立流式 API 探测，也不改变该测试。
- 实施前的公开结果只包含状态、稳定错误码、中文消息、模型、耗时、时间、可选 HTTP 状态和 Codex 版本；本任务为用户显式 API 测试增加会话内 trace，Codex 结果继续保持原摘要契约。
- 用户选择使用独立详情弹窗，默认不增加 Provider 详情页高度。
- 用户希望不进行脱敏；该偏好不能覆盖仓库安全约束。真实 API Key、`Authorization` Header、完整认证内容、代理地址、命令行、环境变量、临时路径和堆栈不得进入 IPC、普通前端状态、日志、通知、快照、测试输出或任务材料。
- 用户已批准：由 API 网络边界生成 trace，并作为同一次测试结果的一部分返回；不新增后端 trace 查询注册表。

## 需求

### TRACE-1 API 测试详情

- API 测试结果在确实构造或发送请求后提供“查看请求与响应”入口；配置在请求构造前失败时不显示入口。
- 详情弹窗展示实际请求方法、最终 `/responses` 地址和 JSON 请求体。
- 详情弹窗展示 HTTP 状态、实际响应正文和耗时；不展示任何 Header。
- Codex 兼容性测试继续只展示现有摘要，不增加 API trace。

### TRACE-2 生命周期与错误

- 请求已构造但未收到响应时，详情仍展示请求，并明确标记未收到 HTTP 响应。
- HTTP 错误、非 JSON/非 Responses 响应、超限响应、网络错误、超时和取消均保持现有稳定状态/错误码语义；若已有可读请求或响应片段，详情可展示它们，不得把部分内容标为成功。
- 响应正文遵守现有 256 KiB 上限；超限时只保留有界片段并明确标记截断。
- Provider 切换、配置指纹变化、结果失效或组件关闭时，trace 与对应结果一起清除；打开/关闭弹窗不发起新请求、不改变测试状态。

### TRACE-3 安全边界

- trace 必须由 Rust 网络边界根据实际请求/响应生成，前端不得根据 Provider 配置重新拼装请求。
- API Key、`Authorization` Header、代理地址和 Codex 临时运行信息不得出现在 trace 或其公开 DTO 中。
- 若 Provider 响应意外回显当前真实 API Key，返回前只移除该密钥字符串；其他非敏感正文尽量保持原样。
- trace 不写入磁盘、备份、日志、通知、localStorage 或普通 Provider DTO。

## 验收标准

- [x] API 测试成功后，结果卡片可通过可访问的入口打开详情弹窗，并看到请求与响应两个清晰区域。
- [x] API 测试收到 4xx/5xx 或无效 Responses 正文时，弹窗仍显示实际 HTTP 状态/正文（在有界范围内），测试状态和稳定错误码保持正确。
- [x] 网络失败、超时、取消或请求构造失败时，详情入口和“未收到响应”状态符合 TRACE-2，不伪造响应。
- [x] 弹窗可通过关闭按钮和 Escape 关闭；关闭不重新发请求，Provider 切换或指纹变化后旧 trace 不可见。
- [x] API 请求仍为 `stream=false`，Codex SSE 测试行为不变。
- [x] DTO 使用稳定 camelCase 字段；没有 Header、API Key、代理地址、临时路径、命令行或环境变量泄漏到前端、日志、Debug、测试输出或任务材料。
- [x] 新增前端、Rust 和跨层测试先因目标行为缺失而失败，再通过专项检查；本轮完成与风险相称的完整质量检查。

## 范围外

- 不把测试记录持久化，不新增历史列表、导出或复制功能。
- 不新增独立流式 API 探测，不替换现有同步 API 探针。
- 不改变 Provider 配置、密钥存储、事务、备份、代理设置或测试计费参数。
- 不修改 Codex 兼容性测试的 SSE gateway、工具门禁或进程环境。
