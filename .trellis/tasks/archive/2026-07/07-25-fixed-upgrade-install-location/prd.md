# 固定升级安装目录并延后旧版卸载

## 目标

调整 Windows NSIS 升级行为：应用内更新沿用原安装目录，手动升级不允许并存安装，并把旧版卸载延后到用户确认之后；保留配置、API Key、日志和备份。

## 已确认事实

- 当前 bundle 是 per-machine NSIS，安装登记使用 HKLM；早期 current-user 版本不在本任务的自动迁移范围内。
- `custom-installer.nsi` 在 `.onInit` 从已登记路径恢复 `$INSTDIR`，但当前普通 GUI 升级页仍允许“不卸载旧版”，且默认在目录页之前调用旧卸载器。
- 应用内 updater 使用被动更新参数，目录页已被跳过并在原目录覆盖；该行为必须保持不变。
- Codex 配置、`%LOCALAPPDATA%\CodexRelay`、API Key、日志和备份由安装目录之外的路径服务管理，升级/卸载不得主动删除。
- 旧 WiX 迁移是兼容性边界，不应因本次 NSIS 升级收紧而被误改。

## 需求

### INST-1 普通 NSIS 升级固定原目录

- 检测到已登记的 NSIS 安装后，安装器必须强制使用已登记的绝对安装目录；GUI 目录选择页不再允许改到第二个目录。
- 新鲜安装仍保留目录选择页、D 盘固定磁盘优先算法和命令行 `/D=` 行为。
- 应用内 updater 的被动/`/UPDATE` 路径行为保持不变。

### INST-2 消除并存安装分支

- 普通 NSIS 升级不再展示“不要卸载/保留旧版”选项。
- 升级过程不得创建第二套程序、覆盖指向旧目录的注册表登记，或留下需要用户猜测的旧卸载入口。
- 用户若要更换安装位置，安装器应明确提示先从 Windows 卸载旧版，再重新运行安装器；本任务不实现一键迁移。

### INST-3 延后破坏性动作并保持数据

- 在用户确认并进入实际安装阶段前，不得调用普通 NSIS 旧卸载器；用户在确认页或安装前取消时，旧程序必须仍可启动。
- 普通 NSIS 原目录升级优先采用与应用内更新一致的原地覆盖路径，保留快捷方式和开机自启；旧 WiX 迁移可保留专用兼容流程。
- 升级、重新安装和卸载不得删除 `.codex`、`%LOCALAPPDATA%\CodexRelay`、API Key、日志或备份。

### INST-4 用户可见说明与契约同步

- README、发布/NSIS 规范和必要的关于页说明必须反映：新安装可选目录，已安装版本升级固定原目录，换位置需先卸载再安装。
- 不在说明、测试输出或任务材料中写入真实密钥或认证文件内容。

## 验收标准

- [x] 结构测试证明现有 NSIS 安装会标记原地升级模式、强制恢复登记目录，并跳过普通升级的目录页。
- [x] 结构测试证明仅剩“上次目录”键而没有 `UninstallString` 时按新鲜安装处理，卸载后重装可以重新选择目录。
- [x] 结构测试证明普通 NSIS 升级不再渲染“不要卸载”分支，且旧卸载调用不发生在用户确认/目录页之前。
- [x] 结构测试证明新鲜安装仍保留目录选择页、固定 D 盘优先和 `/D=` 新装语义；旧 WiX 迁移分支仍存在。
- [x] 文档和用户可见说明与上述行为一致，并明确数据保留边界。
- [x] 专项测试、类型/格式检查和适用的完整检查通过；失败、未执行的真实安装/升级场景如实记录。
- [ ] 在隔离 Windows Sandbox/VM 中分别验证原目录应用内升级、手动同目录升级、取消安装、数据保留和旧版本兼容；未执行项不得声明成功。

## 范围外

- 不实现跨盘一键迁移、复制用户安装目录或自动回滚安装器。
- 不改变 updater endpoint、公钥、签名资产或 Provider/应用数据格式。
- 不自动迁移早期 current-user 版本；继续要求用户先卸载旧版。
