# Provider 页面紧凑布局设计

## 设计目标与边界

本次改动只调整 Providers 页面的信息密度和响应式布局。Provider 状态仍由现有
`ProvidersView` 与子组件提供，所有事件、DTO、composable 和 Tauri 调用保持不变。
样式优先在现有组件边界内完成，避免把布局状态引入业务层。

## 组件与布局方案

### 应用级密度

`App.vue` 的 `ElConfigProvider` 改用 `default` 尺寸。`style.css` 将目前针对所有
Element Plus 控件的 44px 最小高度改为适合桌面窗口的紧凑基线，并保留明确的 focus-visible
轮廓。必要时在局部组件通过 `size="small"` 覆盖，而不是把全局字号或正文全部缩小。

### Provider 详情

`ProvidersView` 保持“列表 + 详情”的双栏结构。所选 Provider 的三项元信息改为
宽屏三列摘要；`provider-switch-controls` 在详情宽度足够时使用两列，低于阈值时恢复
单列。阈值以内容可用宽度为依据，确保 900×620 目标窗口下仍能容纳两个控制卡片。

### Base URL / API Key 控制卡片

两个现有组件继续负责状态和事件，仅调整内部间距、按钮尺寸和 Segmented 展示：

- Segmented 使用 `small`，选项宽度按内容决定，不设置无条件的 `min-width: 100%`。
- 外层保留 `overflow-x: auto` 作为超长选项的最后防线。
- 当前项、管理入口、实际地址和密钥安全提示不删除；管理按钮的短文案不改变 aria 标签。

本任务先不切换为新的下拉组件，避免引入额外状态和测试面；若现有 Segmented 在长选项
验收中仍造成不可用，再以独立后续任务评估按数量切换控件。

### 低频内容顺序

不改变连通性测试和模型偏好的数据逻辑，只通过布局顺序和间距让高频切换区优先进入
首屏。连通性测试不在本任务中新增折叠状态，以避免改变用户现有可见性和自动化测试契约。

## 响应式与可访问性

- 宽屏：列表/详情双栏，详情摘要三列，Base URL/API Key 两列。
- 窄屏：列表/详情单列，摘要和控制卡片单列；页面不产生横向滚动。
- 所有原有按钮、标签、状态文本和 `aria-label` 保留；不以颜色作为唯一状态表达。
- 控件高度下调后仍保持至少约 36px 的常用点击区域，焦点轮廓沿用现有全局规则。

## 兼容性、回滚与风险

这是纯前端可逆改动，不涉及配置迁移、持久化或发布脚本。若在窄窗口、长名称或主题
检查中发现回归，可单独回滚对应 SFC 的 `<style scoped>` 和全局控件基线；业务行为无需
回滚。主要风险是过度压缩导致按钮文案换行或 Segmented 选项难以识别，因此验收重点
放在 900×620、长文本和键盘焦点。
