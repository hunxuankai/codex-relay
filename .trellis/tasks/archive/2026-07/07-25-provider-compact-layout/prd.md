# Provider 页面紧凑布局优化

## 目标

在不改变 Provider 数据、保存流程和密钥安全边界的前提下，降低 Providers 页面垂直占用，
让常用的 Base URL、API Key 和模型偏好在约 900×620 的窗口中可见、可操作，减少用户
必须放大窗口或滚动页面的情况。

## 已确认事实

- `src/App.vue:204` 对整个 Element Plus 应用使用 `size="large"`。
- `src/style.css:86-89` 将按钮、输入框和选择器统一设置为至少 44px 高。
- `src/views/ProvidersView.vue` 当前将 Provider 摘要、Base URL 和 API Key 控件纵向排列。
- `src/components/ProviderEndpointControls.vue` 与 `ProviderCredentialControls.vue` 将 Segmented
  控件设置为至少占满卡片宽度，选项较少时仍显得过宽。
- 前端规范要求约 900×620 的可缩放双栏布局，并在窄窗口下保持可操作。

## 需求

### R1：建立中等密度控件基线

- 全局默认控件密度从 `large` 调整为 `default`。
- 普通按钮和输入控件保持可点击、可聚焦，不低于约 36px；紧凑切换控件可使用 Element Plus `small`。
- 保留清晰的键盘焦点样式、状态文本和明暗主题对比度。

### R2：压缩 Provider 详情首屏

- Provider ID、Wire API、配置状态在足够宽度时以横向摘要呈现，窄窗口自动回退为纵向布局。
- Base URL 与 API Key 控制区在桌面宽度下并排，窄窗口下单列显示。
- 常用切换区位于模型偏好和连通性测试之前；不改变现有交互语义。

### R3：自适应地址/密钥切换器

- Segmented 选项不再被无条件拉伸到整行，使用紧凑尺寸并保留横向溢出保护。
- 现有选项仍可通过键盘和鼠标选择，当前项、管理入口和实际地址/安全提示继续可见。
- 本任务不引入新的明文密钥展示路径。

### R4：缩减非关键留白

- Provider 详情、控制卡片和应用头部的内边距/间距适度降低，避免全局缩小正文文字。
- 管理按钮的可见文案可缩短，但 `aria-label` 和语义必须完整。

## 行为切片与验收标准

### S1：桌面窗口首屏

操作：在约 900×620 的窗口打开已选 Provider。

预期：无需调整窗口大小或滚动，即可看到 Provider 状态摘要、Base URL 当前选项、API Key 当前选项及其管理按钮；键盘 Tab 可到达这些控件。

### S2：窄窗口回退

操作：将窗口缩至窄于桌面双栏阈值。

预期：左右 Provider 列表/详情和 Base URL/API Key 控件按单列排列，无横向页面滚动，控件文字不被截断到无法理解。

### S3：多选项与长文本

操作：使用多个地址/密钥选项及较长名称、URL。

预期：切换器不会撑破卡片或页面；选项可滚动或以合适的紧凑选择方式呈现；实际 URL 可读且不泄漏密钥值。

### S4：回归与主题

操作：执行现有前端测试并检查明暗主题、键盘焦点和 125%/150% Windows 缩放下的页面。

预期：Provider 选择、切换、管理、错误/成功状态行为不变，类型检查和测试通过。

## 范围外

- 不修改 Provider 类型、Tauri 命令、配置文件或密钥存储。
- 不改变连通性测试、备份、通知和权限逻辑。
- 不在本任务中重做整个导航或引入新的页面级折叠系统。

## 约束

- 仅修改 Vue/CSS 及其前端布局测试/契约测试。
- 遵循 Vue 3 Composition API、显式 props/emits、键盘可达和焦点可见规范。
