# Provider 多 Base URL 与 API Key

## 目标

允许用户为同一个 Provider 保存多个带名称的 Base URL 和多个带名称的 API Key，
并在 Provider 详情页通过名称快速识别和独立切换，减少反复手工编辑 Codex 配置与
认证文件的成本。

## 已确认事实与约束

- Codex 官方 Provider 配置中的 `base_url` 是单值，`auth.json` 表示当前 Codex
  使用的文件认证；多项列表、显示名称和非当前 Provider 的密钥预选属于 Relay 私有数据。
- 当前 `config.toml`、`providers.json`、`auth.json` 和
  `provider-preferences.json` 已由同一个 `TransactionService` 保护，任何新增写操作
  都必须继续经过锁、指纹、备份、临时文件、解析、原子替换、写后验证和可验证回滚。
- 普通 Provider DTO、详情页、日志、通知、事件、测试快照和长期前端状态不得包含完整密钥；
  事务备份仍按既有契约保存原始受管文件，可能包含明文密钥。
- 当前处于规划阶段，尚未获得开始实施的批准。

## 功能需求

### R1：命名条目与不变量

- 每个由 Relay 创建或完成纳管的 Provider 必须始终至少有一个 Base URL 和一个 API Key。
- Base URL 与 API Key 是两组彼此独立的列表和选择，不绑定成连接配置。
- 每个条目具有稳定内部 ID、用户名称和实际值；重命名不改变条目身份或当前选择。
- 名称去除首尾空白后必须非空，并在同一个 Provider 的同类列表内按不区分大小写规则唯一；
  Base URL 与 API Key 两个列表之间允许使用相同名称。
- 同一 Provider 内，规范化后的 Base URL 实际值必须唯一，规范化后的 API Key 实际值
  也必须唯一。
- 条目按添加顺序保存和展示；初始项在首位，新项追加到末尾，重命名、替换和切换不改变顺序。
- 不设置条目数量上限，只限制单个字段的长度、格式、唯一性和受管文件解析安全。

### R2：创建与管理

- 新增 Provider 时只录入一个初始命名 Base URL 和一个初始命名 API Key；保存后两者
  成为当前选中项，更多条目从详情页添加。
- Provider 详情页负责快速切换；Base URL 与 API Key 各有独立“管理”入口。
- 管理入口打开专用对话框，可新增、重命名、替换和删除条目。
- 两个管理对话框都使用本地草稿；用户点击统一“保存”后，通过一次事务提交全部变化；
  “取消”不得写文件。
- 当前选中条目不能直接删除，必须先显式切换到其他条目；系统不得按列表顺序自动回退。
- 最后一个 Base URL 和最后一个 API Key 都不能删除，不再提供把受管 Provider 清空为
  无密钥状态的正常操作。
- 若批量草稿修改了当前选中 Base URL 或 API Key 的实际值，保存事务必须同步对应的
  Codex 生效文件。

### R3：详情页与密钥查看器

- 详情页使用两行 `ElSegmented` 分段按钮分别展示 Base URL 名称和 API Key 名称；
  条目较多或窗口较窄时允许横向滚动。
- 当前 Base URL 的实际地址显示在选择器下方；普通 API Key 区域只显示名称和状态，
  不显示密钥值或可逆片段。
- API Key 管理对话框同时承担密钥查看器职责。打开对话框即视为用户明确请求查看，
  一次加载该 Provider 的全部密钥到对话框局部状态，并默认明文显示。
- 每个密钥提供复制操作；对话框提供“隐藏全部/显示全部”切换。
- 关闭密钥管理对话框后，完整密钥不得保留在普通详情状态、全局状态、localStorage
  或其他持久化前端存储中。

### R4：选择与生效语义

- 点击 Base URL 只改变 Base URL 选择，点击 API Key 只改变 API Key 选择。
- 点击命名项不会自动启用非当前 Provider。
- 当前 Provider 切换命名项后立即同步对应 Codex 生效配置，并提示重启 Codex。
- 非当前 Provider 切换命名项时只更新该 Provider 的预选状态，不改变全局当前 Provider，
  也不把其密钥写入 `auth.json`；用户显式点击“使用此 Provider”时，预选 URL、密钥、
  模型和推理强度一起生效。
- 外部修改冲突、写入失败或验证失败时，整个选择或批量管理操作必须失败并回滚，不能
  留下部分更新。

### R5：外部配置与不完整 Provider

- 外部 `config.toml` / `auth.json` 值若与某个已保存条目一致，只读状态自动映射到该名称。
- 未匹配的外部值显示为临时“外部地址”或“外部密钥”，不得在刷新或启动时自动追加、
  覆盖或持久化。
- 用户必须显式执行“保存为命名地址”或“导入当前密钥”并填写合法名称，才能把未知
  外部值纳入 Relay 管理。
- 从外部发现且缺少 Relay 密钥记录的 Provider 仍可安全展示并进入补齐入口，但标记为
  配置不完整；补齐至少一个命名密钥前不能应用或运行可用性测试。
- 未知外部密钥的普通 DTO、界面、日志、通知和测试输出只暴露状态，不暴露值或可逆片段。

### R6：兼容读取

- 兼容范围只覆盖当前单 Base URL / 单 API Key 格式到本功能规范格式，不猜测更早或
  未知格式。
- 现有 `base_url` 规范化为已选中的“默认地址”，现有已保存 API Key 规范化为已选中的
  “默认密钥”；没有已保存密钥的外部 Provider 保持配置不完整，不自动认领 `auth.json`。
- 启动、列表读取和普通刷新不得为了迁移而写文件；只有后续用户发起的成功事务才把
  规范结构写回，并正常创建备份和执行写后验证。

### R7：测试与安全

- 现有用户显式触发的 API/Codex 可用性测试使用目标 Provider 当前选中的 Base URL
  与 API Key；测试失败不得改变选择或受管文件。
- 完整密钥只允许通过专用管理命令返回，并且 Rust `Debug`、公开错误、日志、事件、
  通知和普通序列化必须继续脱敏。
- 自动化测试只使用安全临时目录和 `test-key-*-not-real` fixture，不得访问或修改真实
  `%USERPROFILE%\.codex` 与 `%LOCALAPPDATA%\CodexRelay`。

## 可观察行为切片

1. 通过 Provider 创建公开接口提交初始 URL 名称、URL、密钥名称和密钥后，列表返回
   两个已选中的命名项；立即应用时 `config.toml`、`auth.json`、`providers.json` 和
   `provider-preferences.json` 在同一事务后保持一致。
2. 通过 Base URL 批量管理公开接口新增、重命名、替换和删除非当前项时，顺序与稳定 ID
   保持正确；修改当前项的 URL 会同步 `config.toml`，任一无效草稿使整批不写入。
3. 通过 API Key 管理查询接口显式打开管理器时，只返回目标 Provider 的完整密钥集合；
   通过批量保存接口提交草稿后，修改当前密钥会同步当前 `auth.json`，普通列表仍不返回密钥。
4. 通过详情选择公开接口操作当前 Provider 时，URL 或密钥立即生效；操作非当前 Provider
   时不改变全局当前 Provider，密钥不写入当前 `auth.json`。
5. 通过 Provider 切换公开接口应用非当前 Provider 时，使用其预选 URL、密钥、模型和推理
   强度；缺少命名 URL、命名密钥或模型偏好时拒绝切换且不修改文件。
6. 读取当前单值格式时，列表在内存中显示“默认地址”与“默认密钥”但不写文件；第一次
   成功修改后写成规范结构，并保留原值及无关 TOML 内容。
7. 外部 URL/密钥匹配已有值时，列表映射到已有名称；未知值显示临时外部状态，显式命名
   纳管前不会写入私有列表。
8. 外部修改冲突、临时解析失败、替换失败、写后验证失败或回滚失败时，公开错误码稳定，
   不泄漏密钥，并且不存在 URL、密钥、认证或偏好部分更新。
9. 前端用户可通过两行分段按钮独立切换，通过两个管理对话框批量编辑；密钥对话框打开即
   可查看、复制和隐藏/显示全部密钥，关闭后局部密钥状态被清空。
10. 用户显式运行 API/Codex 测试时，测试使用目标 Provider 当前选择；成功、失败或取消均
    不改变选择或受管文件。

## 验收标准

- [ ] 新建 Provider 时可输入初始 URL 名称、URL、密钥名称和密钥；保存后四项完整保留，
  初始 URL 与密钥处于选中状态。
- [ ] 同一 Provider 可新增至少两个命名 Base URL 和两个命名 API Key，并按添加顺序在
  详情页显示。
- [ ] 两组分段按钮支持鼠标和键盘独立切换，选中状态不只依赖颜色；约 760px 窄窗口下
  仍可操作。
- [ ] 当前 Provider 切换 URL 或密钥后，Relay 状态与 `config.toml` / `auth.json` 一致；
  非当前 Provider 的选择不会改变全局当前 Provider 或当前 `auth.json`。
- [ ] 应用非当前 Provider 时，其预选 URL、密钥、模型和推理强度一起进入生效配置。
- [ ] 空名称、同类重复名称、重复实际值、无效 URL、空密钥、删除当前项及删除最后一项
  均被前后端拒绝，且文件保持不变。
- [ ] 重命名、替换值、保存、重新加载和应用重启后，稳定 ID、当前选择和条目顺序保持正确。
- [ ] 管理对话框中的多项修改全部成功或全部回滚，不会部分保存；指纹过期时要求重新加载。
- [ ] 打开 API Key 管理对话框即可查看、隐藏/显示和复制全部密钥；关闭后密钥不留在普通
  前端状态或持久化存储中。
- [ ] 普通 Provider DTO、详情页、日志、通知、事件、错误和测试快照不包含完整密钥；复制操作
  也不会把密钥写入应用通知或日志。
- [ ] 外部值匹配时映射到已有名称；未知外部值只显示临时状态，显式命名导入前不会写文件。
- [ ] 外部无密钥 Provider 被标记为配置不完整，在补齐前不能应用或测试。
- [ ] 当前旧格式可只读加载且不会触发启动写入；第一次成功修改后通过事务写成规范结构，
  原 URL、密钥、模型偏好和未知 Codex 配置内容均不丢失。
- [ ] API/Codex 测试始终使用目标 Provider 当前选择，测试成功或失败都不自动切换。
- [ ] 临时写入、解析、替换、写后验证或回滚故障不会留下 URL、密钥、认证和元数据之间的
  混合状态。
- [ ] 路径安全测试证明真实默认目录前后递归快照完全不变，所有 fixture 密钥均符合
  `test-key-*-not-real`。

## 范围外事项

- Base URL 与 API Key 配对成连接配置。
- 自动轮询、随机或负载均衡。
- 请求失败后自动切换、定时健康检查或自动故障转移。
- 批量导入、拖拽排序和上下移动排序。
- 在线同步、团队共享、密钥加密或系统凭据库集成。
