# 备份文件列表与记事本打开

## 目标

让用户在“备份与恢复”页面中直接确认每份事务备份实际包含的文件，并可用 Windows
记事本打开任一备份文件进行查看，无需先在文件资源管理器中定位备份目录。

## 已确认事实

- 每份事务备份以独立目录保存，允许的文件只有 `config.toml`、`auth.json`、
  `providers.json` 和 `metadata.json`。
- `metadata.json` 始终存在；其余三个文件是否存在由备份元数据中的存在状态记录。
- 当前备份页只支持列出备份和恢复，没有文件列表与打开文件入口。
- 产品面向当前 Windows 用户的个人可信计算机场景。用户已明确接受直接用记事本打开
  可能包含明文 API Key 的 `auth.json` 和 `providers.json`，不需要额外警告或二次确认。

## 需求

- 每条备份记录提供“查看文件”按钮。
- 点击按钮后，在当前备份卡片内展开该备份实际包含的文件列表；再次点击可收起。
- 同一时间最多展开一条备份记录，展开另一条时自动收起上一条。
- 文件列表仅显示实际存在的快照文件，`metadata.json` 始终显示。
- 点击任一文件项，直接使用 Windows 记事本打开对应文件。
- `config.toml`、`auth.json`、`providers.json` 和 `metadata.json` 使用相同行为，
  不增加敏感信息提示或确认步骤。
- 打开失败、备份文件缺失或请求无效时，在备份页显示安全、明确的错误消息，且不影响
  备份恢复功能。
- 前端不得接收备份文件内容或可用于访问任意文件的绝对路径；后端只能打开所选备份
  目录内允许的四种文件。
- 文件内容、API Key 和完整文件路径不得写入日志、通知或普通前端状态。

## 验收标准

- [x] 每条备份卡片显示“查看文件”按钮和原有“恢复”按钮。
- [x] 点击“查看文件”后，卡片内显示该备份实际存在的允许文件；不存在的快照文件不显示。
- [x] `metadata.json` 始终出现在有效备份的文件列表中。
- [x] 同一时间只展开一条备份；再次点击当前按钮可收起。
- [x] 点击列表中的文件会请求后端使用 `notepad.exe` 打开该文件。
- [x] 后端拒绝未知文件类型、路径穿越、备份目录外文件和缺失文件。
- [x] 打开成功时无需额外提示；失败时页面显示错误，恢复按钮仍可使用。
- [x] 前端接口与状态中不包含备份文件内容或绝对路径。
- [x] Rust 测试覆盖文件列表、允许文件解析、缺失文件和路径安全；Vue 测试覆盖展开、
  单卡片展开、打开动作与错误展示。

## 范围外事项

- 应用内文件内容预览或编辑。
- 调用用户自定义编辑器或修改默认程序关联。
- 打开非事务备份的 `settings-*.json` 或 `.corrupt-*` 保护性副本。
- 修改备份格式、保留数量、恢复语义或 API Key 存储方式。
