# 修复前端按钮悬停文字不可见并审计同类状态

## 目标

修复编辑 Provider 页面“清空密钥”按钮在鼠标悬停后文字不可见的问题，并审计所有
Element Plus 按钮的自定义样式，确保悬停、按下、聚焦和禁用状态都保持可读；把根因和
可执行的预防规则沉淀到项目规范与回归测试中。

## 已确认事实

- `src/components/ApiKeyInput.vue:54-65` 使用 `ElButton type="danger" plain`；同一组件
  的 `.danger-link` 在 `:104-107` 直接设置 `color: var(--danger)`。
- Element Plus 的危险纯按钮在 hover 时通过 `--el-button-hover-text-color` 将文字切换为
  白色、背景切换为危险色。组件 scoped 样式的直接 `color` 与 Element Plus hover 规则处于
  同等优先级且后加载，因而会把 hover 文字重新固定为危险色；危险背景下形成低对比度，
  与截图中的空白按钮文字一致。
- 全局检索发现其余危险/主要按钮没有同样的“按钮类直接覆盖 `color`”模式；导航当前态和
  普通布局类只影响有意的静态状态或尺寸，需要在修复后再次验证。
- `src/style.css` 已有危险按钮禁用态可读性变量，但没有覆盖 hover 的回归契约。

## 需求

### R1：清空密钥按钮状态可读

保留现有清空确认交互；按钮在默认、悬停、按下、键盘聚焦和禁用状态下，文字与背景均
保持可辨识，并继续使用项目危险色主题。

### R2：全局同类样式审计

检查所有 `ElButton`（包括 `plain`、`text`、`link`、`primary`、`danger`、`warning`）
及其 scoped/global 覆盖，修复任何会覆盖组件状态文字/背景颜色的同类问题；不改变按钮的
业务动作、禁用条件或确认流程。

### R3：回归保护与规范沉淀

增加一个因当前缺陷失败、通过修复后通过的前端回归契约，覆盖“语义按钮状态颜色由
Element Plus 变量控制，不在按钮装饰类上写静态 `color` 覆盖”。更新前端规范/任务记录，
明确按钮自定义样式只负责布局，颜色应使用组件 `type`/主题变量或显式状态选择器。

## 验收标准

- [x] “清空密钥”按钮在 hover 时仍显示可读文字，且默认/聚焦/禁用状态未回归。
- [x] 全局审计有明确结果；发现的同类问题已修复，未改变无关按钮行为。
- [x] 回归测试先在旧实现上因正确原因失败，再在修复后通过；专项测试、类型检查和适当的
      全量前端检查有本轮命令证据。
- [x] 项目规范或任务注记记录根因、检查清单和以后避免直接覆盖 Element Plus 状态颜色的
      规则；不包含真实密钥或用户目录数据。

## 范围外

- 不更换 Element Plus 组件库、不调整业务色板、不修改 Provider/API Key 持久化逻辑。
- 不把截图或真实用户配置写入仓库。
