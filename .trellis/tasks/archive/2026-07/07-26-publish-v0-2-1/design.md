# Codex Relay v0.2.1 发布设计

## 发布边界

本任务把已经实现并通过前端检查的更新信息展示修复组织为 `v0.2.1` 候选，不扩展产品范围。产品提交与版本/说明提交完成后，本地运行完整检查和无私钥普通构建；远端工作流生成 Draft updater 资产，审计通过后公开，再从隔离的 `v0.2.0` 基线验证真实应用内升级。

```text
本地修复
  -> 产品修复提交
  -> 版本/发布说明同步
  -> 完整检查 + 无私钥普通构建
  -> 候选提交并推送 origin/main
  -> workflow_dispatch
  -> v0.2.1 Draft Release
  -> 说明/版本/资产/签名关系审计
  -> 公开并复核 Latest
  -> Sandbox/VM 中 v0.2.0 -> v0.2.1 升级验证
```

## 版本与说明

- `v0.2.0` 之后只有向后兼容的界面缺陷修复，使用补丁版本 `0.2.1`。
- `releaseBody` 聚焦两项用户价值：发布日期不再显示原始 ISO 字符串；更新说明按 Markdown 排版并在渲染前清理不安全内容。
- 升级说明明确从 `v0.2.0` 更新到 `v0.2.1`，继续保留 Tauri updater 签名、可能出现未知发布者和不删除用户数据的说明。

## 信任与秘密边界

- 本地普通构建显式移除签名环境变量，不读取或输出私钥。
- GitHub Actions 仅在既有 Tauri 构建步骤使用 Secret；本任务只核对名称和非秘密元数据。
- Draft/公开审计只记录 Release 元数据、资产大小、SHA-256、URL 和签名一致性。
- 不读取、复制、显示或持久化 GitHub Token、私钥、真实 API Key、认证 Header 或用户文件内容。

## Draft 与失败处理

- Draft 是公开前唯一门禁。目标提交、版本、说明、资产数量、平台、URL 或签名任一不一致即停止公开。
- Actions 失败时保留失败步骤并调查根因；只有新候选提交完成本地回归和完整检查后才重试。
- 已公开版本不原地替换资产。

## 隔离升级

复用 `scripts/windows-sandbox/` 的主机与 guest 脚本，以公开 `v0.2.0` 安装器为基线。staging 必须是系统临时目录真子路径且无 reparse point，输入映射只读、结果映射可写；`before.json` / `after.json` 只保存相对路径、长度、SHA-256 和安装元数据。
