# 修复发布后 cleanup Run 的标签筛选

## 目标

让发布控制台正确找到由已公开版本标签触发的 cleanup Run，避免历史清理成功却显示“完成但有警告”。

## 已确认事实

- 用户在发布 `v0.5.2` 后遇到 cleanup 未确认警告，并询问是否需要修复该查询缺陷；本任务继续处理该问题。
- cleanup Run `34469403040` 已成功，`headBranch=v0.5.2`；Release 与 tags 只剩 `v0.5.2`。
- 同一 workflow、release 事件与发布时间条件下，`--branch main` 返回空列表；本轮 `--branch v0.5.2` 返回上述成功 Run。
- `SystemGhBackend` 的 CleanupRuns 当前把分支固定为 main，服务与编排只传发布时间，丢失了已公开版本的标签上下文。

## 需求

- 查询绑定已公开 Release 的标签和发布时间，同时保持固定仓库、cleanup workflow 与 release 事件过滤。
- 对返回的 Run 再核对标签和时间，不把其他版本的清理 Run 当作当前版本结果。
- 成功清理进入正常完成；真实失败或无法确认仍保留警告，已公开 Release 的成功证据继续保留。
- 测试与开发只使用安全临时路径和 mock，不访问真实 Codex 配置或密钥；不重新触发真实清理、发布或删除任何资产/tag。

## 验收标准

- [x] 原生 gh 查询参数的回归先失败，再证明实际使用目标标签。
- [x] 验证目标标签识别、其他标签排除、缺失/非法标签拒绝及成功/失败结果区分。
- [x] 验证发布编排把已核验的 Release 身份完整传到 cleanup 查询。
- [x] 通过本轮完整检查与控制台构建，提供实际 EXE 和哈希。

## 范围与交付

修复范围为 cleanup Run 的只读发现链路；不重写历史完成会话、不修改删除策略、不为此重发主应用。
按 Trellis 完成必要验证、精确提交、归档和日志后，普通推送已配置的 origin/main，并报告 SHA 核验结果。
