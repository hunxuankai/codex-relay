# 修复发布计划的发布说明校验阻塞

## 目标

修复发布控制台在检查仓库、把线上 `0.5.1` 的目标版本设为 `0.5.2` 后，点击“生成发布计划”被 `RELEASE_NOTES_REQUIRED_CONTENT_MISSING` 拦截的问题，让维护者可以继续预览和确认发布候选。

## 背景与已确认事实

- 用户报告的错误发生在生成计划时，尚未进入候选发布。
- `tools/release-console/src-tauri/src/services/release_notes.rs` 校验版本标记、三个必需段落、安全提示与秘密内容。
- `tools/release-console/src-tauri/src/services/release_application.rs` 对传入的说明直接校验，仅在没有传入说明时根据正式 Latest 和 Git 提交生成。
- 修复前 `tools/release-console/src/App.vue` 从恢复会话读取说明，并将任何非空说明交给新计划；回归测试已确认 `0.5.2` 请求实际携带旧 `v0.5.0 → v0.5.1` 正文。

## 需求

- R1：首次生成新版本计划时使用与当前仓库、正式公开版本及目标版本一致的说明，不把上一轮发布说明误用为新版本输入。
- R2：同一计划的人工说明编辑仍可重新校验和生成计划；错误说明仍受现有安全门禁保护。
- R3：恢复已有发布会话保留历史事实；切换目标版本或仓库时不允许启动旧计划。
- R4：提供本轮测试和构建证据，生成可用的更新后发布控制台，按项目授权提交并推送代码。

## 验收标准

- AC1：恢复已完成的 `0.5.1` 会话，预检线上 Latest 为 `v0.5.1`，输入 `0.5.2` 并生成计划后，使用新版本说明，不传入旧版本说明。
- AC2：同一版本计划修改说明后重新生成，继续传入维护者编辑内容；校验失败不改变安全边界。
- AC3：切换仓库或目标后旧计划失效；异步旧响应不得恢复过期计划或说明。
- AC4：针对性回归和完整 `npm run check` 通过，实际构建发布控制台并记录产物信息。

## 范围外

- 本任务修复发布控制台并提供新构建，不直接公开 `0.5.2` Release，不创建或推送 Tag。
- 不放宽发布说明的版本、段落、未知发布者、数据保留或秘密扫描规则。
- 不读取或操作真实 Codex/Relay 配置、密钥和数据，不把测试通过写成真实安装或升级证据。
