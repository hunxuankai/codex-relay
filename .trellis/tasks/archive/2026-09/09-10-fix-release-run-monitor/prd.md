# 修复发布控制台远端 Run 监控中断

## 目标

修复发布控制台在 GitHub Run 仍正常执行时提前终止监控、且只展示泛化错误的问题，使查询中断、真实远端失败和可恢复会话具有可核验的结果。

## 已确认事实

- 用户提供的 2026-09-10 发布日志记录：候选版本 `0.5.2`、候选 SHA `fe39d72a2f88898ce1db7e476cacac1c90f34857`、Run `34454972967`。
- 该日志中本地检查、普通构建与推送均返回成功；08:30:20 UTC 远端仍为 `in_progress`，08:30:25 UTC 控制台报 `RELEASE_REMOTE_FAILED`。
- 本轮通过 `gh run view` 只读核验：该 Run 于 08:42:22 UTC 变为 `completed/success`，完整检查和 Draft 构建均成功。因此现有日志不能证明远端 Run 失败。
- 用户要求继续处理此故障；允许在现有安全与发布边界内诊断、修复、验证并提交推送。Trellis 生命周期和最终代码修改、检查由主会话负责。

## 需求

- R1：定位远端监控查询、错误映射和恢复路径中的中断原因；区分证据充分的结论与历史日志已丢失的信息。
- R2：正常排队或运行中的 Run 不得因短暂的只读查询故障直接成为不可恢复的发布失败。重试有界，不重复触发 Run。
- R3：持续查询失败、监控预算耗尽、真实 Run 失败和响应不可信时保留稳定、脱敏、可操作的错误证据；不虚报成功。
- R4：已经推送并记录 Run 身份的会话可安全继续同一远端 Run；恢复不重复本地构建、提交、推送或远端派发。
- R5：所有测试使用 mock 和安全临时目录；不读取真实 Codex 配置、认证或应用数据，不在输出与任务材料中保存秘密。

## 验收标准

- [x] 确认当前 Run 与 Draft 的真实只读状态，记录可复核的 ID、SHA、状态与时间。
- [x] 通过回归测试复现单次查询故障导致提前失败的问题，并证明修复后继续同一 Run 到正常结果。
- [x] 验证查询连续失败仍有界停止，保留底层安全错误类别；真实远端失败和身份异常不被重试掩盖。
- [x] 验证重启后恢复监控及必要的旧失败会话兼容，不引入重复派发或伪回滚。
- [x] 通过本轮专项、完整检查与必要的控制台构建；更新相关契约并记录未执行项。

## 交付要求

精确暂存、提交、归档及会话日志后普通推送已配置上游，核验远端跟踪 SHA 与本地 HEAD 一致。
该交付出口按 Trellis 3.4/3.5 的顺序执行，最终提交哈希、推送结果与 SHA 比对证据必须在收尾答复中报告。

## 范围外

- 不自动公开、删除或替换 Release/Draft，不重新派发实际发布工作流，不推送 Tag。
- 不修改 Provider、真实配置、安装/卸载、签名或数据保留行为。
- 日志中的 PowerShell 中文乱码和前端 bundle 提示不作为本次故障修复范围。
