# 完善发布控制台网络与仓库同步

## 目标

让中国大陆等 GitHub 网络不稳定环境中的维护者，可以在发布控制台内配置代理、验证 Git/GitHub 连通性、识别具体网络失败阶段，并在安全条件满足时把已审核的本地提交同步到远端 `main`；程序重启后还能清晰恢复发布会话。

## 背景与事实

- 仓库预检会执行 `git fetch --prune origin main`，后续发布同时依赖 Git Push 与 GitHub CLI。
- 控制台目前只继承启动进程环境中的代理变量，没有用户可见、跨启动持久化的代理设置。
- `GIT_COMMAND_FAILED` 会折叠启动、超时、命令失败和进程树错误，无法指导维护者处理网络问题。
- 发布候选流程已经只提交并推送控制台生成的固定候选文件；新增同步能力用于发布前已经存在、且本地严格领先远端的审核提交。
- 发布会话状态保存在仓库 Git 元数据目录中，可以支持进程关闭、崩溃和网络中断后的恢复。

## 需求

### R1：跨启动代理设置

- 提供启用开关、代理类型、地址、端口和“测试连接”。
- 首版代理类型仅支持 HTTP 与 SOCKS5。
- 保存开关、类型、地址和端口并在下次启动恢复；关闭开关时保留已填写内容。
- 地址只接受主机名、IPv4 或 IPv6，不接受协议、路径、查询、片段、账号、密码或 URL userinfo；端口必须为 `1–65535`。
- 不提供自动模式或单独的直连选项：开关打开表示使用自定义代理，关闭表示强制直连。

### R2：一致的网络执行边界

- Git 与 GitHub CLI 必须使用同一代理设置快照。
- 开关打开时，自定义代理必须覆盖继承环境和 Git 全局代理配置。
- 开关关闭时，必须清除继承代理并覆盖 Git 全局代理配置，确保实际直连。
- 发布计划、候选 Push、GitHub Run、Draft 审计、公开与恢复操作均使用动作开始时的当前代理设置。
- 代理账号、密码、Token、Authorization Header 和完整认证文件不得进入普通前端状态、localStorage、日志、错误、通知、测试输出、任务材料或导出摘要。

### R3：连接测试与错误诊断

- “测试连接”只读验证目标仓库的 Git 远端读取与 GitHub API 访问，不修改仓库、不触发工作流。
- 界面分别显示 Git 与 `gh` 的成功/失败、耗时和安全消息；测试不是仓库检查或发布的强制门禁。
- Git/GitHub 失败至少区分代理配置无效、进程启动失败、超时、命令失败、远端移动和推送后验证失败。
- 错误只展示失败阶段、稳定错误码、安全中文消息和建议动作，不回显原始敏感 stderr。

### R4：安全同步本地提交

- 仓库检查应区分已同步、领先、落后和分叉，并返回对应数量与领先提交主题。
- 只有工作区干净、远端为 `hunxuankai/codex-relay`、本地严格领先 `origin/main`、不落后、不分叉且没有活动发布冲突时，才显示“推送当前 N 个提交”。
- 确认对话框必须展示远端、本地与远端短 SHA、提交数量和提交主题，并明确不推送 Tag 或其他分支。
- 用户确认后，后端必须重新 Fetch 并验证工作区、远端 SHA、领先关系和本地 HEAD；远端变化时停止。
- Push 只允许精确 RefSpec `<已确认本地 SHA>:refs/heads/main`，不得 force push、推送 Tag、其他分支或未提交内容。
- 推送后重新读取远端 `main`；只有远端精确等于已确认 SHA 才算成功，随后自动重新检查仓库。
- 仓库已同步时不显示同步入口；落后或分叉时只显示阻止原因。

### R5：发布会话自动检测与恢复

- 恢复已记住的仓库路径后，只通过本地 Git 元数据自动检测持久化会话，不执行 Fetch 或 GitHub 请求。
- 自动检测不自动继续任何网络或发布动作。
- 未完成会话显示目标版本、阶段、候选短 SHA 和对应恢复动作：本地中断要求取消并验证回滚；已提交未 Push 继续 Push；远端 Run/Draft 继续监控；等待公开进入审核确认。
- 已完成、失败或取消的会话只提供“查看上次结果”，不显示为待恢复。
- 不存在会话时不显示原“加载活动会话”入口。
- 恢复远端操作时使用用户当前保存的代理设置。

## 验收标准

- [x] AC1：有效代理设置跨启动恢复；损坏、未知版本或存储异常安全回退，且不包含任何认证字段。
- [x] AC2：HTTP 与 SOCKS5 都能生成统一的 Git/`gh` 运行配置；关闭开关时继承环境和 Git 全局代理均被覆盖为空。
- [x] AC3：连接测试返回 Git 与 GitHub API 两项结果和耗时，不写仓库、不触发 GitHub 工作流。
- [x] AC4：Fetch、Push 和 GitHub API 的启动失败、超时与命令失败具有不同稳定错误码和安全消息。
- [x] AC5：仓库检查对已同步、领先、落后、分叉返回权威状态；只有符合全部安全门禁的领先状态携带 Push 预览。
- [x] AC6：安全 Push 在确认后重新验证远端，只推送精确 SHA 到 `refs/heads/main`，远端移动或验证失败时不报告成功。
- [x] AC7：启动时自动检测已记住仓库的会话；未完成、终态和无会话分别显示正确入口，且检测过程保持本地只读。
- [x] AC8：前端类型、Tauri command、Rust DTO 使用一致的 camelCase 契约；组件保持 typed props/emits，App 只负责编排。
- [x] AC9：专项测试、前后端完整检查和发布控制台重新打包通过，并记录交付 EXE 的路径、大小、时间与 SHA-256。

## 范围外

- 不提供任意仓库、任意远端、任意分支、force push、Tag 推送或通用 Git 客户端能力。
- 不保存代理账号、代理密码、GitHub Token 或其他认证秘密。
- 不修改 Windows 系统代理、用户环境变量或 Git 全局配置文件。
- 不把本任务的代理配置扩展到正式 Codex Relay 主应用。
