# Codex Relay v0.2.0 发布设计

## 发布边界

本任务只把 `v0.1.2` 之后已经完成并归档的改动组织为一个可审计的 `v0.2.0` 发布候选，不新增产品行为。版本元数据与最终发布说明进入候选提交；GitHub Actions 使用现有 Tauri updater 信任根生成 Draft 资产；公开 Release 后再从隔离的 `v0.1.2` 基线执行真实应用内升级。

```text
本地 master（v0.1.2 后 66 个提交）
  -> 版本与 releaseBody 更新
  -> 完整检查 + 无私钥普通构建
  -> 发布候选提交并推送 origin/main
  -> workflow_dispatch
  -> GitHub Actions 完整检查与 updater 构建
  -> v0.2.0 Draft Release
  -> 资产/说明/签名审计
  -> 公开 v0.2.0
  -> Sandbox/VM 中 v0.1.2 应用内升级验证
```

## 版本决策

`v0.1.2` 之后包含多项向后兼容的新能力，而非单一缺陷修复，因此按 SemVer 提升次版本到 `0.2.0`。版本权威来源仍为 `package.json`，其余 npm lock、Cargo 元数据和结构测试必须与之相等。

## 发布说明结构

最终 `releaseBody` 分为三部分：

1. “更新内容”：概括用户可见能力，不罗列内部任务或提交。
2. “更新方式”：说明 `v0.1.2` 用户可在应用设置中检查更新，也可手动下载安装器。
3. “注意事项”：保留未知发布者、升级数据保留和旧数据格式兼容边界。

主要用户可见主题：

- Provider 支持多命名 Base URL 与多命名 API Key，并保存模型及推理强度偏好。
- 新增 Provider API 可用性与 Codex 兼容性测试、代理选择，以及脱敏的请求/响应详情。
- 新增应用网络代理、本机代理检测、启动/周期更新提醒和设置页手动更新。
- 统一 Element Plus 交互与主题，优化 Provider 页面布局、通知和自检错误跳转。
- 备份页支持查看实际备份文件并改进旧版备份元数据兼容。
- 已登记 NSIS 升级固定沿用原安装目录。

内部 Rust crate 拆分和开发反馈优化不作为主要用户卖点，可在说明中省略或合并为稳定性改进。

## 信任与秘密边界

- 普通本地构建不注入或读取 updater 私钥。
- 发布构建只在 GitHub Actions 的 Tauri 构建步骤读取既有 Secret；仅核对 Secret 名称和更新时间。
- Draft/公开审计可以下载公开或已授权访问的资产，但只记录大小、SHA-256、版本、URL、签名关联和非秘密 Release 元数据。
- 不把 GitHub CLI Token、私钥、密码、Authorization Header、真实 API Key 或用户文件内容写入命令输出、Trellis 材料或提交。

## Draft 与公开门禁

Draft 是公开前的唯一审计点。以下任一不一致都停止发布并删除错误 Draft：目标提交、版本、最终说明、NSIS 资产、独立 `.sig`、`latest.json`、平台集合、资产 URL、内联签名。只有 Draft 审计通过才切换为公开；公开后只做只读复核，不修改同版本资产。

## 隔离升级设计

复用仓库 `scripts/windows-sandbox/` 安全入口，把公开 `v0.1.2` 安装器复制到系统临时目录的真子路径。guest 只使用 `test-key-*-not-real` fixture 与成对 Relay 覆盖；`before.json` / `after.json` 只保存相对路径、长度、SHA-256 和安装元数据。应用内升级的交互动作与 UAC 观察可由用户或受支持的 Windows 控制工具完成，脚本负责结果验证。

## 回滚与失败处理

- 本地检查或构建失败：不提交候选，修复后重新运行完整门禁。
- Actions 失败：不发布，记录失败步骤并以新提交重新运行。
- Draft 错误：删除错误 Draft 和资产，修正源码/工作流后重新生成。
- 公开前发现产品缺陷：停止本任务的发布阶段，先完成独立修复。
- 公开后发现缺陷：不得替换 `v0.2.0` 资产，发布严格更高版本修复。
- Sandbox/VM 不可用或交互未完成：保留“公开发布已完成、真实升级未验证”的明确限制。
