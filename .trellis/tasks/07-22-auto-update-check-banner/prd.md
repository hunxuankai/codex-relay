# 增加自动更新检查与页头提醒

## 目标

让 Codex Relay 在应用运行期间主动发现新版本，避免用户必须进入设置页手动检查；发现更新后，在主界面页头下方持续提供明确提醒，并可一键进入设置页完成现有的下载与安装流程。

## 已确认事实

- 当前更新检查仅由设置页 `UpdatePanel` 手动触发，底层通过 Tauri updater 访问固定更新源，并沿用设置中的网络代理。
- 当前 `useUpdater` 每个组件实例独立持有检查结果和 updater session；页头与设置页若各自创建实例，会产生状态割裂和 session 生命周期问题。
- 主界面没有 Vue Router，页面切换由 `App.vue` 的 `activeView` 控制；页头下方已有自检错误横幅及跳转模式可复用。
- 应用关闭到托盘时进程继续运行，因此“每小时”可按应用进程存活时间调度；完全退出后定时器自然停止。
- 现有产品文档明确声明“不在启动或后台自动访问更新源”，本功能需同步修改该契约及相关测试。

## 需求

- R1：应用完成必要启动状态加载后，自动检查一次更新。
- R2：应用进程持续运行时，每隔一小时自动检查一次更新。
- R3：自动检查必须使用当前已保存且启用的更新代理配置；代理设置后续变化时，下次检查读取最新值。
- R4：发现新版本后，在应用页头下方显示更新提醒，至少包含新版本号和进入设置页的操作。
- R5：点击提醒操作后切换到设置页，并让设置页复用同一份更新状态与可安装 session，用户无需再次检查即可继续现有“下载并安装”流程。
- R6：手动检查与自动检查共享并发保护，不能因启动检查、小时检查或用户点击而并发访问更新源。
- R7：组件卸载或应用退出时清理小时定时器及 updater session，不遗留后台任务。
- R8：不改变现有签名校验、安装确认、下载进度和错误安全映射规则。
- R9：启动与小时自动检查失败时静默处理，不显示页头错误或应用通知；设置页手动检查失败仍显示现有安全错误。
- R10：首次设置引导页显示期间仍执行启动更新检查；发现更新时保存结果但不打断引导，进入正常主界面后再显示页头提醒。
- R11：更新提醒与系统自检错误提醒同时存在时均显示；更新提醒紧贴页头，自检错误提醒位于其下方，两者分别跳转到设置页和自检页。
- R12：`App.vue` 持有唯一的应用级 updater 控制器，并通过显式 props/events 与更新提醒、设置页及 `UpdatePanel` 共享状态和动作；不使用模块级单例或隐式全局状态。

## 验收标准

- [x] AC1：应用进入正常主界面后触发且只触发一次启动更新检查。
- [x] AC2：使用可控假定时器证明每经过一小时触发一次检查，重复挂载/卸载不会叠加定时器。
- [x] AC3：检查进行中时，自动或手动重复触发不会开始第二个并发检查。
- [x] AC4：无新版本时不显示页头更新提醒；发现新版本时显示版本号和明确操作按钮。
- [x] AC5：点击页头更新提醒后切换到设置页，设置页直接展示已发现版本并允许继续确认下载与安装，不再次请求更新源。
- [x] AC6：自动检查读取当前保存的代理；代理变化后，下一轮读取新代理。
- [x] AC7：自动检查失败不显示页头错误或应用通知，也不会被误报为“已是最新版本”或“发现更新”；随后手动检查仍可正常执行并显示失败信息。
- [x] AC8：现有手动检查、安装确认、进度展示和错误处理测试继续通过。
- [x] AC9：README/相关规范不再声明应用不会启动检查或后台轮询，并准确描述新的网络访问行为。
- [x] AC10：首次设置引导显示时仍触发一次检查；发现更新不会替换或遮挡引导页，进入主界面后提醒可见。
- [x] AC11：更新和自检错误同时存在时，两个横幅按确认顺序同时可见且各自导航正确。
- [x] AC12：从自动检查发现版本后进入设置页不会创建第二个 updater session 或再次访问更新源，仍可完成确认安装流程。

## 范围外

- 自动下载或自动安装更新。
- 强制更新、跳过版本、更新提醒关闭开关。
- 应用完全退出后的系统级定时检查。
- 二进制自动回滚或发布流程变更。
