# 构建 Codex Relay 发布控制台

## 目标

为 Codex Relay 维护者提供独立的 Windows 发布控制台 EXE，把当前分散在本地命令、Git、GitHub Actions、Draft Release 页面和发布后复核中的操作串成可视化、可恢复、可审计的一键发布流程，显著降低人工操作时间和误发布风险。

## 背景与已确认事实

- 用户明确要求实施，并确认期望形态是独立 EXE 软件。
- 控制台只服务当前 Codex Relay 仓库，不设计为通用跨项目发布平台。
- 当前正式链路使用 `.github/workflows/release.yml`、`workflow_dispatch` 和固定 SHA 的 `tauri-apps/tauri-action`，先生成 Draft Release。
- 当前 GitHub 默认分支是 `main`；本地分支名称可以不同，但发布候选必须以精确 SHA 推送到并验证远端 `main`。
- 应用版本当前分布在根 npm 包、主 Tauri Cargo 包、`codex-relay-core` Cargo 包及相应锁文件中。
- 最终简体中文发布说明同时进入 GitHub Release 描述和 `latest.json.notes`。
- 更新签名私钥和密码只允许存在于 GitHub Actions Secrets；控制台不得读取、保存或输出 Secret 值。
- 正式公开前必须核对候选提交、版本、说明、NSIS、`.sig`、`latest.json`、哈希和签名关联。
- 真实 `%USERPROFILE%\.codex` 与 `%LOCALAPPDATA%\CodexRelay` 不得作为开发、测试或发布工具状态目录。
- 发布电脑需要已有 Git、Node/npm、Rust/Cargo、GitHub CLI 和有效 `gh auth login`；发布构建和 updater 签名仍由 GitHub Actions 完成。
- 用户确认首版不执行 Windows Sandbox、真实应用内升级、UAC、安装、重启或数据保留验证。

## 需求

### R1：独立开发者工具

- 生成独立于正式 Codex Relay 产品的便携 Windows EXE，不进入普通用户安装包，也不改变正式应用的更新入口、运行时权限或产品数据。
- 首版只支持 Windows、`hunxuankai/codex-relay` 和 GitHub 默认分支 `main`。
- 控制台不自带或下载 Node、Rust、Git、GitHub CLI、更新私钥或认证文件。

### R2：发布输入与预检

- 自动定位或允许选择仓库，并读取当前本地版本、公开 Latest、当前提交、上游关系、工作区状态、远端状态、活动发布 Run、既有 Draft 和工具链可用性。
- 只允许从干净、已同步且远端身份精确匹配目标仓库的工作区开始；计划外改动、非快进、远端漂移、活动发布 Run 或冲突 Draft 必须停止流程。
- 允许维护者选择修复、功能、大版本或输入严格更高的 SemVer。
- 自动读取当前公开 Latest 对应提交到候选提交之间的 Git 历史，按稳定规则生成简体中文发布说明草稿；首版不调用外部 AI。
- 草稿必须包含可编辑的更新内容，以及自动生成并校验的更新方式、上一版本、目标版本、无 Authenticode 提示和数据保留说明。
- 在任何文件写入、提交、推送或远端发布动作前展示版本、说明、计划文件、目标远端和候选摘要。

### R3：候选准备与精确提交

- 用户点击“开始发布”后，由控制台在一个受控事务中同步 `package.json`、`package-lock.json`、主/核心 Cargo manifest、`Cargo.lock` 和权威发布说明文件。
- 写入必须保留未知 JSON/TOML 内容，Cargo manifest 使用 `toml_edit` 局部修改，并在失败或取消时恢复全部原始字节和存在状态。
- 自动运行发布专项测试、`npm run check`、无 updater 私钥的普通 `npm run build`、产物枚举、差异检查和秘密扫描。
- 只有全部本地门禁通过后，才精确暂存计划文件，创建 `chore(release): 准备 v<版本> 发布` 提交并推送远端 `main`。
- 提交和推送前后都重新验证文件集合、候选 SHA 和远端 SHA；不得宽泛暂存或把计划外文件加入发布提交。

### R4：远端工作流与 Draft 审计

- 控制台通过 GitHub CLI 的结构化输入触发唯一发布工作流，传递预期版本和候选 SHA；工作流必须在创建 Draft 前验证实际 Run SHA 和版本一致。
- 可视化展示排队、环境准备、完整检查、Draft 构建及 Post 步骤的状态和真实耗时。
- Action 成功后自动发现唯一目标 Draft，并审计：Release ID、tag、标题、候选提交、`draft=true`、`prerelease=false`、最终说明、且仅有 NSIS、`.sig`、`latest.json` 三项资产。
- 下载 Draft 资产时通过已登录的 `gh` 认证边界直接写入安全临时文件；日志和 UI 不显示 Token 或 Authorization Header。
- 审计 `latest.json.version`、`notes`、平台、URL、内联签名与独立 `.sig`，并记录三项资产的实际大小和 SHA-256。

### R5：人工公开与在线复核

- 保留两个明确的人工作业门禁：开始候选发布，以及 Draft 全部审计通过后的正式公开。
- “确认公开”按钮只有在重新获取并重新审计同一 Draft 身份后才可执行；使用 Release ID 更新 `draft=false`，不得按模糊标题或最新对象猜测。
- 公开后自动复核 `releases/latest`、tag ref、公开 `latest.json`、资产身份与 Draft 证据一致，并监控历史 Release 清理工作流。
- 在线复核失败或清理部分失败必须保留真实失败状态，不得把 Release 已公开等同于全部收尾成功。

### R6：状态机、恢复与可观察性

- 可视化阶段至少包含：预检、候选预览、版本事务、专项检查、完整检查、普通构建、安全审计、提交推送、远端 Run、Draft 审计、等待公开、在线复核和历史清理。
- 每阶段记录稳定 ID、状态、开始/结束时间、耗时、退出码、失败分类、脱敏日志和证据摘要。
- 同一仓库同一时间只允许一个活动发布会话；控制台和 GitHub 端都要防止重复运行。
- 控制台重启后可从 Git worktree 专属 Git 元数据目录恢复会话；恢复时重新验证工作区、候选提交、远端 SHA、Run 和 Draft，不得只信任旧状态文件。
- 候选提交创建前的失败或取消必须完成可验证回滚；候选提交已创建但 push 失败时保留 `Committed` 检查点并只重试 push。push 后不得伪造回滚，而是从已完成的远端阶段继续或明确报告人工处置要求。
- 自动生成不含秘密的发布结果摘要；未执行、失败和人工步骤必须如实保留。

### R7：安全边界

- 不在 argv、stdin 持久化、日志、状态文件、UI、测试输出或 Git 中写入 GitHub Token、updater 私钥、私钥密码、Authorization Header、真实 API Key 或完整认证文件。
- 子进程不通过通用 shell 拼接命令，只允许固定的 Git、npm、Cargo 和 `gh` 可执行文件及结构化参数；继承环境使用明确白名单，并移除 Codex/API/签名/GitHub Token 环境变量。
- 状态、事务备份和日志只写入所选 worktree 的 Git 元数据专用目录；临时下载只写入系统临时目录的安全子目录，退出后清理。
- 控制台不得读取或写入真实 Codex 配置和正式 Codex Relay 应用数据。
- 正式公开、错误 Draft 删除等不可逆动作必须单独确认；首版不自动删除错误 Draft。

### R8：首版明确范围

- 首版实现从本地候选准备到 GitHub Release 正式公开及在线复核的可视化一键流程。
- 首版不执行 Windows Sandbox、真实应用内升级、UAC、安装、重启、卸载或数据保留验证，界面和结果摘要不得暗示这些行为已经验证。
- 首版不建设通用插件系统、跨仓库模板、团队权限、远程控制台、自更新或无人值守自动公开。

## 可观察行为切片与测试边界

### B1：仓库预检

- 公开接口：检查仓库命令，输入仓库路径。
- 操作：读取 Git/GitHub/工具链状态，不写源码。
- 预期：返回可发布摘要或稳定失败码；远端不匹配、脏工作区、落后/领先、活动 Run 和 Draft 冲突分别可见。
- 测试边界：Git 行为使用真实临时仓库和本地 bare remote；GitHub/工具探测通过可替换命令后端模拟，不访问真实远端。

### B2：版本与说明计划

- 公开接口：生成候选计划，输入目标 SemVer。
- 操作：从固定 Git 提交列表生成说明，并计算全部目标文件的新内容和指纹。
- 预期：相同输入产生稳定草稿；低于或等于 Latest、缺失必需说明或秘密模式命中时失败且零写入。
- 测试边界：纯转换不 mock；文件只使用临时 fixture；前端 mock typed Tauri service。

### B3：候选事务与本地门禁

- 公开接口：开始发布命令，输入已确认计划并通过 typed Channel 输出进度事件。
- 操作：事务写入版本/说明，运行专项、完整检查和普通构建。
- 预期：成功时产生经验证候选；任一写入、命令、取消或并发冲突在推送前恢复精确原字节。
- 测试边界：事务使用真实临时文件；命令执行以可替换后端注入成功/失败/超时/取消；Windows 进程树使用专项测试。

### B4：精确提交与推送

- 公开接口：发布状态机内部 Git 阶段。
- 操作：只暂存计划文件，提交并推送远端 `main`。
- 预期：安全临时 remote 收到唯一候选提交；计划外文件、远端竞态或非快进失败，不执行远端工作流。
- 测试边界：使用真实临时 Git 仓库和 bare remote，不 mock Git；不得操作真实仓库远端。

### B5：远端 Run 与 Draft

- 公开接口：继续/恢复发布命令，通过 Channel 输出 Job/Step 事件。
- 操作：触发工作流、轮询 Run、发现并审计 Draft。
- 预期：版本/SHA 不一致、Run 失败、资产缺失/多余、说明漂移、签名不一致或哈希失败都会禁用公开。
- 测试边界：`gh` 命令与下载后端使用固定 JSON/二进制 fixture；自动化测试不创建真实 Run、Release 或 tag。

### B6：正式公开与复核

- 公开接口：确认公开命令，输入会话 ID 和界面展示的 Draft 身份。
- 操作：重新审计同一 Release ID 后公开，并验证 Latest、tag、manifest 和清理 Run。
- 预期：身份漂移立即失败；公开成功和清理失败分别记录，不能合并为单一成功。
- 测试边界：GitHub API 全部 mock；只验证结构化请求、对象身份和状态机公开行为。

### B7：重启恢复

- 公开接口：加载活动会话、取消会话和导出摘要命令。
- 操作：读取 Git 元数据目录中的原子状态文件并重新查询真实外部状态。
- 预期：可安全恢复到最近已验证阶段；损坏状态、指纹漂移或对象不存在返回稳定错误，不覆盖源码或远端。
- 测试边界：状态存储使用临时 Git dir；外部状态通过 mock 服务；损坏、旧版本和写后失败均有测试。

### B8：可视化交互

- 公开接口：`src/services/tauri.ts` typed client 和单一发布会话 composable。
- 操作：选择仓库、编辑版本/说明、开始、观察步骤、查看错误、确认公开、恢复和导出。
- 预期：组件只消费只读状态和显式动作；按钮禁用原因、键盘焦点、错误文本、窄窗口与明暗主题可用。
- 测试边界：Vitest mock typed Tauri client/Channel，不启动真实文件、进程、GitHub 或 Codex 数据访问。

## 验收标准

- [ ] AC1：可生成并启动独立便携 Windows EXE，且正式 Codex Relay 主程序和 NSIS 不包含发布控制台。
- [ ] AC2：安全临时仓库中可完成预检、候选预览、版本事务、精确提交和本地 bare remote 推送；真实 Codex/Relay 用户目录哨兵不变。
- [ ] AC3：所有版本来源和发布说明的计划变更在写入前可见；取消或候选提交创建前失败不会留下部分写入，commit 后 push 失败会保留可恢复的唯一提交检查点。
- [ ] AC4：固定 Git 历史生成稳定且可编辑的中文说明草稿；最终 workflow 使用的说明文件与确认内容一致。
- [ ] AC5：计划外文件、远端漂移、非快进、重复会话、活动发布 Run 和冲突 Draft 均安全失败。
- [ ] AC6：本地命令和 GitHub 操作具有脱敏日志、超时、取消、退出码和稳定失败分类；取消会终止整个 Windows 进程树。
- [ ] AC7：未通过 Draft 版本、候选提交、说明、资产集合、哈希和签名关联审计时，正式公开操作不可用。
- [ ] AC8：正式公开前重新验证同一 Release ID；公开后 Latest、tag、manifest、资产和清理状态分别复核并报告。
- [ ] AC9：控制台重启后可恢复会话，并重新验证外部状态；损坏或过期状态不会触发写入或远端动作。
- [ ] AC10：状态、日志、测试输出和 Git 差异不包含真实秘密、认证 Header、完整认证文件或用户数据。
- [ ] AC11：相关 Vue、Rust、脚本、发布结构、安全和路径隔离测试通过，并完成本轮独立 EXE 实际构建和产物枚举。
- [ ] AC12：成功页只报告实际完成的候选准备、检查、构建、Draft、公开和在线复核，不报告 Sandbox、安装、UAC 或应用内升级成功。

## 范围外事项

- 通用跨项目发布平台、插件系统、团队权限与远程控制。
- updater 私钥下载、本地签名、GitHub Token 管理、Secrets 或公钥轮换。
- Windows Authenticode、自更新和面向普通用户的控制台分发。
- Windows Sandbox、真实安装/升级/UAC/重启/卸载/数据保留验证。
- 自动删除错误 Draft、无人值守正式公开或修改已经公开版本的资产。
