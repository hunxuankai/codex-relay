# 修复发布远程 Run 失败设计

## 根因与边界

测试同时跨越 Node 与 PowerShell 两个 Windows 路径边界。Node 从 `%TEMP%` 继承的路径可能包含
8.3 短目录名，而 PowerShell `Get-Item` 会把同一文件报告为长路径。原断言直接比较两个字符串，
因此把“路径表示不同”误判为“产物错误”。生产脚本返回真实产物完整路径的行为保持不变，修复仅
调整结构测试的 fixture 与路径身份断言。

## 数据流

1. 测试在系统临时目录创建唯一长目录，并通过 `cmd.exe` 从该目录的工作目录取得 8.3 路径表示。
2. 源 fixture 位于真实临时目录，目标目录参数使用短路径别名。
3. PowerShell 脚本复制 EXE，并返回产物路径、大小、最后写入时间和 SHA-256。
4. 测试分别对返回路径和预期路径执行文件系统真实路径解析，再比较两者身份；随后独立校验字节、
   大小和 SHA-256。

真实路径解析同时承担存在性门禁：如果脚本报告不存在或错误位置，测试会在比较前失败，不会因为
放宽字符串形式而漏检错误产物。

## 方案权衡

- 采用：测试比较两端解析后的真实路径。它直接表达“同一个文件”的契约，并覆盖短名、长名和路径
  大小写等 Windows 表示差异。
- 不采用：让生产脚本回显调用者传入的路径。这会降低构建证据质量，并把运行时输入别名泄漏到
  后续消费者。
- 不采用：删除路径断言。仅保留哈希无法证明脚本报告的路径就是实际交付位置。

## 兼容性与回滚

改动不改变生产 API、发布 workflow、产物布局或数据格式，只影响 Windows 结构测试。若验证发现
真实路径解析在支持环境中不稳定，可回滚测试改动；不需要迁移或清理产品数据，也不触发远端发布。
