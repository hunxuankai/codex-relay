# 发布控制台固定日志区域

## 目标

让维护者执行发布时始终能看到当前及已完成步骤的诊断日志；任一步骤失败后，失败前后的相关输出
仍可在当前窗口和重启恢复的同一发布会话中查阅，足以判断具体失败点，而不是只得到退出码或通用摘要。

## 背景与已确认事实

- 当前“实时证据”位于右侧可滚动工作区中，不是窗口下方固定区域
  （`tools/release-console/src/App.vue:231`、
  `tools/release-console/src/components/release/ReleaseStepDetails.vue:37`）。
- 前端已定义并消费 `stepLog` 事件，但生产 Rust 后端没有构造或发送该事件
  （`tools/release-console/src/types/release.ts:195`、
  `tools/release-console/src-tauri/src/models.rs:289`）。
- 本地门禁使用的 `SafeProcessRunner` 已支持进程完成前流式输出；当前发布后端调用时把 event sink
  设为 `None`，并在命令结束后只保留退出码和耗时
  （`tools/release-console/src-tauri/src/infrastructure/local_verification.rs:69`）。
- 当前前端在开始新发布和加载持久化会话时清空内存事件；重启后只能恢复失败步骤，不能恢复日志
  （`tools/release-console/src/composables/useReleaseSession.ts:141`、
  `tools/release-console/src/composables/useReleaseSession.ts:157`）。
- 现行发布规范禁止原始 stdout、stderr、环境变量、代理 URL、认证信息和真实密钥直接进入事件或
  持久化会话（`.trellis/spec/release/publishing.md:469`）。该安全边界继续适用，但不得把经过安全
  处理的诊断内容退化为无上下文摘要。

## 需求

### R1 固定布局

- 桌面窗口使用标题、上方发布工作区、下方日志区三行布局；日志区始终留在视口底部，上方时间线和
  发布工作区独立滚动。
- 窄窗口中上方内容改为单列共同滚动，日志区仍保持可见；不得遮挡操作或产生页面横向溢出。

### R2 混合诊断日志

- 每个发布阶段至少记录结构化的开始、关键进度、完成或失败证据。
- 本地 npm/Cargo 门禁额外实时记录经过安全处理的 stdout/stderr，保留测试名、相对文件位置、
  行列、错误正文、退出码、耗时和相邻上下文。
- Git、GitHub CLI 与远端轮询记录操作类型、状态变化、定期心跳、稳定错误码、Run/Job/Step 和失败
  结论；发布 Run 与 cleanup Run 都必须覆盖状态变化和 5 分钟无变化心跳，不原样倾倒认证相关输出
  或大段机器 JSON。

### R3 当前会话持久化

- 安全结构化日志保存到实际 Git 元数据目录的
  `<git-dir>/codex-relay-release-console/session.log.jsonl`，与现有 `session.json` 同级。
- 只保留当前发布会话；新会话开始时原子轮换旧日志。每条记录携带 session ID 和递增 sequence，
  会话不匹配时不得混入。
- 恢复或继续发布同一会话时从持久化有效前缀恢复最后 sequence、计数与截断状态；不得从 1 重新编号
  或覆盖已有日志。
- 关闭 WebView 不停止日志落盘；重启并加载同一仓库会话时恢复日志。删除仓库后无需继续保留。

### R4 有界存储与分页

- 单会话硬上限为 `50 MiB`、`100,000` 条记录，单条记录硬上限为 `1 MiB`，任一上限先到即执行
  有证据的有界保留。
- 实时输出按不超过 `64 KiB` 的小块写入；超长单行拆为连续记录，不等待单条上限才刷新。
- 达到上限时优先保留阶段、警告、错误和最新输出；淘汰最旧普通输出并写入截断标记。
- 恢复时先加载最新 `2,000` 条及统计信息；历史记录通过 sequence 游标分页读取，单次 IPC 不传输
  整个日志文件，界面任意时刻最多渲染一页。
- 实时 `stepLog` 只进入有界日志页状态，不得同时累积到通用发布事件数组或其他无界前端状态。

### R5 失败与恢复

- 步骤失败前先刷新 stdout/stderr 未完整片段，再追加稳定错误码和安全失败消息；此前日志继续保留，
  后续未执行步骤不得生成伪日志。
- 不完整尾行可忽略并产生恢复警告；中间记录损坏时保留此前有效日志并停止读取后续不可信记录。
- 日志读取、轮换或写入失败不得改写真实发布结果，但当前窗口必须显示一次明确警告，说明重启后
  可能丢失日志。

### R6 安全诊断边界

- 原始 stdout/stderr、环境变量、代理 URL、Authorization、Token、真实密钥、完整认证文件、命令行
  和不必要的绝对路径不得进入 IPC、日志文件、通知、Debug、测试输出或任务材料。
- Rust 边界复用现有秘密脱敏，并移除 ANSI 控制符、把仓库绝对路径规范化为相对路径；敏感值使用
  明确占位符替换，不能删除非敏感错误上下文。
- fixture 只使用 `test-key-*-not-real`，开发和自动化测试不得访问真实 `.codex` 或
  `%LOCALAPPDATA%\CodexRelay`。

### R7 日志区交互

- 日志区显示时间、步骤或命令 ID、`lifecycle/stdout/stderr` 来源和保留换行的诊断文本。
- 最新页默认跟随新增日志；用户滚动离开底部或查看历史页后暂停跟随，并可返回最新。
- 提供“更早”“更新”“返回最新”“复制当前页”，显示当前范围、总条数、截断状态和失败提示。
- 日志区可聚焦、可键盘滚动，长行换行，使用文本插值而非 `v-html`，并适配浅色与深色主题。

### R8 发布语义保持

- 不改变候选回滚、取消、会话互斥、提交、推送、GitHub Run、Draft 审计、公开审批、在线复核或
  cleanup 的成功/失败判定。
- 日志持久化失败不能被报告为发布失败，发布失败也不能因日志系统异常而被报告为成功。

## 可观察行为切片

1. 启动包含可观测输出的本地门禁；命令结束前，最新日志页已出现对应步骤、来源和诊断文本。
2. 本地门禁输出多行后非零退出；未完整片段先刷新，随后显示稳定错误码，候选回滚与时间线状态保持
   现有真实语义。
3. Git push、GitHub Run、Draft 审计或在线复核异常；日志保留对应操作、状态变化、Run/Job/Step、
   耗时和安全失败结论。
4. 输出包含假密钥、Bearer、代理 URL、ANSI 和仓库绝对路径；公开日志只保留安全占位符、相对路径和
   非敏感错误上下文。
5. 日志达到 `50 MiB`、`100,000` 条或单条 `1 MiB` 任一上限；文件和前端状态保持有界，出现截断
   记录，真实发布结果不变。
6. 失败后关闭并重启控制台；加载同一仓库会话恢复最新页并可读取更早页，开始新会话后旧日志不显示。
7. 在 900x620 与窄窗口中滚动上方内容、浏览历史日志并返回最新；日志区始终可读且不遮挡操作。

## 验收标准

- [ ] AC1（R1、R7）：900x620 与窄窗口中日志区固定在主内容下方，上方区域可滚动且无重叠、截断
  控件或页面横向溢出。
- [ ] AC2（R2）：本地门禁真实诊断输出在进程完成前可见；每个其他发布阶段至少产生结构化开始、
  关键进度、完成和失败证据。
- [ ] AC3（R2、R5、R8）：失败后已有日志、失败步骤、稳定错误码和安全消息同时可见，时间线仍准确
  区分已完成、失败和未开始步骤，回滚/取消语义不变。
- [ ] AC4（R3、R5）：同一会话跨重启恢复且可分页读取；新会话、其他仓库、损坏记录和旧事件通道
  不得混入当前日志。
- [ ] AC5（R4）：达到 `50 MiB`、`100,000` 条或单条 `1 MiB` 任一上限时显示截断证据，持久化文件、
  单次 IPC、日志页和通用事件状态保持有界。
- [ ] AC6（R6）：Rust 权威边界测试证明假密钥、Authorization/Bearer、Token、代理地址、环境值和
  绝对测试路径不泄漏，同时保留测试名、相对位置、错误正文、退出码和上下文。
- [ ] AC7（R7）：最新跟随、历史分页、返回最新、复制、失败提示和键盘滚动通过组件测试；日志文本
  不使用 `v-html`。
- [ ] AC8（R8）：既有发布取消、回滚、会话互斥、失败进度、Git/GitHub 和远端发布测试继续通过，
  完整项目检查与发布控制台构建通过。

## 范围外事项

- 把发布控制台扩展成任意命令终端或允许执行自定义命令。
- 展示、复制或导出未经安全处理的 stdout/stderr、环境变量、命令行或认证数据。
- 建立多会话日志归档、把完整日志并入发布摘要，或在仓库删除后继续保留日志。
- 改变正式 Codex Relay 应用日志系统、安装包、签名、升级或卸载数据保留策略。
- 在本任务中重试失败发布、创建或公开 Release、执行安装、升级或卸载验证。
