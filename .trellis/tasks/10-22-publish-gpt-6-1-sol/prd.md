# 发布 GPT-6.1 Sol 更新

## 目标

把 `main` 上已完成的 GPT-6.1 Sol 支持发布为 Windows 正式更新，让既有客户端通过固定 Latest 清单发现并下载。

## 已确认事实

- 用户明确要求“发布更新吧”，已授权候选准备、提交推送、工作流触发、审计通过后的公开发布和项目既有历史 Release 清理。
- 初始 `main` 与 `origin/main` 同步，HEAD 为 `80b1730069fe408201c50518481d9ee125c6b301`，工作区干净。
- 本地版本及公开 Latest 均为 `0.5.2`；公开 Release ID 为 `386122082`，目标提交为 `fe39d72a2f88898ce1db7e476cacac1c90f34857`。
- 目标补丁版本为 `0.5.3`。预检中没有目标 Release/Tag，没有活动发布 Run，GitHub Actions 状态为 operational，两个 updater Secret 名称均存在；未读取值。
- 待发布能力为 `gpt-6.1-sol`，默认 `low`，支持 `low / medium / high / xhigh / max / ultra` 和 Fast；此后端目录已驱动编辑与详情选项。
- v0.5.2 后另有两项发布控制台修复：Run 查询中断/失败会话恢复，以及 cleanup Run 标签归属筛选。

## 需求

- R1：发布 `v0.5.3`，版本、锁文件与最终简体中文发布说明一致；说明准确描述新增模型及已包含修复。
- R2：本轮完整检查与不依赖 updater 私钥的普通 Windows 构建通过，记录实际 EXE/NSIS 大小、时间、SHA-256。
- R3：唯一发布 Run 绑定版本与候选 SHA，CI 完整检查通过后仅生成 Draft；同一候选不盲目重跑。
- R4：核对 Draft 身份、候选提交、说明、安装器、独立签名、Latest 清单、大小、哈希与更新公钥签名后，公开同一 Release ID。
- R5：公开 Latest、tag 与公开下载内容和 Draft 证据一致；记录历史清理 Run 和前后 Release/Tag 列表。
- R6：只使用临时测试目录和成对 Relay 覆盖，不读取真实 Codex/Relay 数据或签名秘密；普通非强制推送，不本地推送 Tag。
- R7：收尾时提交发布证据、归档与会话日志，最终 main/远端 SHA 一致；未实际执行的安装、UAC、应用内升级、重启与卸载明确保持未验证。

## 验收标准

- [ ] 版本六文件与说明一致，发布结构/请求验证和完整 `npm run check` 通过。
- [ ] 无 updater 私钥普通构建退出 0，实际产物信息已记录。
- [ ] 候选提交普通推送成功，唯一 CI Run 的 SHA、版本、最终结果已记录。
- [ ] Draft 三项资产审计与更新签名验证通过，随后同一 Release 正式公开。
- [ ] 公开 Latest、tag、清单和资产复核通过，历史清理 Run 和列表复核完成。
- [ ] 证据、归档和日志均提交并推送，最终远端与 HEAD 一致。

## 范围外

不改变模型能力、更新信任根、安装/卸载行为；本轮不以真实用户环境执行安装、应用内升级、UAC 或数据保留验证。
