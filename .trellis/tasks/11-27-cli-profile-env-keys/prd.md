# 管理 CLI Profile 的环境变量凭据

## 目标

用户已用 `agentrouter.config.toml`、`qiandao.config.toml` 和 `codex -p <名称>` 并行使用多个供应商，各 Key 由环境变量提供。希望 Relay 能发现这些配置、解释凭据状态，并在首版从软件内设置或更换 Key，直接写入原生 CLI 所引用的变量。

用户已明确批准按本首版范围实施。

## 首版需求

- **R1 · 区分使用方式**：默认供应商切换维持原样。CLI Profile 是按次启动的配置，不设置全局「当前 Profile」；在供应商页以独立子页发现已有 Profile，无须导入或迁移。
- **R2 · 说明实际引用**：展示 Profile 名称、解析到的供应商、变量名和独立/继承关系。未解析、不受支持或碰到共享变量时解释原因，不能把无法判断标成「未设置」。
- **R3 · 应用内设置和更换 Key**：对明确绑定的供应商专用变量，提供「设置/更换 Key」，明确保存到 Windows 当前用户环境变量；未设置可新建、已设置可替换。系统、共享、通用或无法确认的变量保留外部管理入口，只读且说明原因。不回显旧值、不另存密钥副本；已运行的进程不随保存改变。
- **R4 · 保留原生启动**：提供只含 Profile 名称的「复制启动命令」，不改默认配置或认证状态，不启动 Codex，也不联系供应商。显示 Relay 正在查看的 Codex 配置目录。
- **R5 · 安全提交**：仅用户显式保存才更改一个目标用户变量，不改 TOML、默认认证或 Relay 密钥库；检测配置/变量冲突，写后回读验证，失败时区分已恢复和结果无法确认，不盲目覆盖外部修改。

## 验收标准

- [x] R1：测试目录中两个已有 Profile 可同时列出并分别复制命令；进入、刷新、离开页面都不写文件，不改变原有默认供应商或托盘行为。
- [x] R2：用 Profile 名、Provider ID、变量名互不相同的 fixture 验证实际关联；覆盖从默认配置继承、同名变量大小写冲突、单文件损坏、不支持的认证方式与不确定的路由。单文件错误不影响可正确解析的其他条目。
- [x] R3：对未配置或已配置的专用变量，保存后回读 Windows 用户范围的值并刷新状态，另一个供应商变量保持原样。系统同名、共享、通用、无法解析或不受支持的变量不能直接保存。状态区分用户变量、Relay 进程可见、未检测到和无法检测，提示现有进程及启动脚本覆盖的限制。
- [x] R4：命令中的 Profile 名称通过安全校验；不可信名称不生成命令。复制、刷新、打开或取消编辑均不写变量；首版不发起供应商网络请求。
- [x] R5：模拟外部改动、写失败、提交/回读失败及回滚失败，确认不误报成功。对回滚验证原值和存在状态，确认 Profile、默认选择和既有认证文件不变；应用不把新旧 Key 写入普通响应、日志、命令行、剪贴板或通用快照。

验收使用隔离注册表、临时配置、假值和受控 UI；未验证真实用户环境或发布资产，详见 [验证记录](verification.md)。

## 不纳入首版

- 新建、改名、删除或迁移 Profile；管理系统级变量、全局删除变量、自动读取 PowerShell 启动脚本；将 Profile 作为独立账户或历史目录。
- 一键启动、进程注入、应用内密钥库、密钥版本历史、自动可用性测试，以及在 Relay 和系统之间复制或双向同步密钥。
