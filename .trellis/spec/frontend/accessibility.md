# 可访问性与界面行为

## 语义与键盘

- 交互使用原生 `button`、`input`、`label`、导航和对话框语义，不用仅带 click 的 `div`。
- 所有按钮和表单控件可通过键盘到达，焦点态清晰可见。
- 图标按钮提供可理解的 `aria-label` 或可见文本。
- 对话框支持明确标题、取消/确认动作和合理的焦点管理。
- 对话框若通过 `nextTick` 或 `setTimeout` 延迟聚焦，必须保存并在 `onBeforeUnmount` 清理 timer，
  同时阻止卸载后的异步回调访问 DOM；组件在 SSR 或 DOM 环境销毁后应安全短路。
- Provider API 请求/响应详情使用独立只读对话框：入口名称包含 Provider，Escape 和关闭按钮都可
  关闭，点击遮罩也可关闭，关闭后焦点返回原入口；测试中请求/响应区分别使用可读 loading 文本
  与 `aria-busy`，长 URL、请求正文和有界响应正文必须可滚动且不造成页面横向溢出。
- Provider 排序手柄必须是可聚焦按钮，具有包含 Provider 名称的 `aria-label`；除鼠标拖动外，
  上下方向键必须产生同一重排动作。busy 或列表不足两项时手柄禁用，排序状态不能只靠透明度或
  颜色表达。

## 状态表达

- 当前 Provider、无密钥、无效配置、warning/error 不能只靠颜色区分。
- 禁用操作仍要说明原因，例如当前 Provider 禁止删除、缺少密钥禁止启用。
- 成功切换同时提供应用内提示与 Windows 通知，并包含“请重启 Codex 后生效”。
- 备份页不得显示备份快照中的明文密钥。

## 布局与主题

- 保持约 900×620 的可缩放双栏布局，并在窄窗口下可读可操作。
- 桌面密度以普通控件至少 36px、显式紧凑控件至少 32px 为基线；通过减少无效留白、
  横向摘要和响应式网格提高信息密度，不通过小于 13px 的正文或难以命中的点击目标压缩页面。
- 900×620 下应优先让当前 Provider 摘要、Base URL、API Key 和模型偏好进入首屏；
  地址/密钥选项较多时允许控件内部横向滚动，但页面本身不得产生横向滚动。
- 颜色使用 CSS 变量跟随系统明暗主题；文本与控件保持足够对比度。
- 避免复杂动画和会阻碍操作的过渡；系统托盘关闭语义要和真正退出明确区分。

## 测试点

组件测试至少覆盖标签关联、按钮可用/禁用原因、延迟焦点卸载清理、焦点可见相关 CSS 契约、36px/32px
密度基线、错误/成功文本和窄窗口关键布局类。布局改动还需在 900×620 与窄于 620px
的视口验证网格列数和页面横向溢出；真实托盘和 Windows 窗口行为需要人工或系统级证据，
不能由单元测试代替。
